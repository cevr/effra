# 2026-10-27: the Go-shaped language ("Effect for Go")

Labels: **Checked (prototype)** and **Proposed**. Source: the design sketches of 2026-10-26 (numbered 8, 9 and 10) and the merged prototype compiler [`prototypes/sketch9`](../../prototypes/sketch9/README.md). The normative text is [`docs/spec/`](../spec/README.md), v0.

- The Checked snippet checks with the prototype's compiler, not `ef check`, because the current `ef` front end implements the earlier language. Command, from `prototypes/sketch9` at commit `ce6540d5`: `go run ./cmd/sketchc check <file>` exits 0, and `go run ./cmd/sketchc build <file> -out <dir> -o <bin>` builds a program that prints `paid auth-7`. The snippet is `testdata/checkout.sketch` with `report` folded into `main`.
- Proposed snippets are designed in [`docs/spec/`](../spec/README.md) and not yet implemented. The spec names the ticket that implements each.

## What changed

Effra now reads as Go. Go is the only target (owner, 2026-10-26). Effect stays the reference for the guarantees, and the standard library restates what Effect does in Go's idioms. The `effect fn`, `run`, `raises { }` and `service` forms of the 2026-10-08 preview give way to Go functions with two rows:

| 2026-10-08 | 2026-10-27 |
| --- | --- |
| `service Users { effect fn get(…) … }` | `type Users interface { Get(…) … }` |
| `raises { NotFound }` | `error[NotFound]` in the result |
| `uses { Users }` | `uses Users` |
| `run Users.get(id)` | `try Users.Get(id)` |
| `.provide<S>(p)` | `with(Live) { … }` and `wire Live { … }` |
| `.catch<E>(h)` | `catch { case E: … }` |
| `.timeout(ms)` | `timeout.After(500ms) { … }` |

## Checked (prototype): rows, wire and timeout

```go
package checkout

import "timeout"

type OrderNotFound struct{ ID string }
type GatewayDown struct{}

type Order struct {
	ID    string
	Total int64
}

type Payment interface{ Pending | Authorized | Declined }

type Pending struct{}
type Authorized struct{ AuthID string }
type Declined struct{ Reason string }

type Orders interface {
	Find(id string) (Order, error[OrderNotFound])
}

type Gateway interface {
	Authorize(order Order) (Payment, error[GatewayDown])
}

func checkout(id string) (string, error[OrderNotFound | GatewayDown | timeout.Expired]) uses Orders, Gateway, Scheduler {
	order := try Orders.Find(id)
	payment := try timeout.After(500ms) { Gateway.Authorize(order) }
	switch p := payment.(type) {
	case Pending:
		return "pending"
	case Authorized:
		return "paid " + p.AuthID
	case Declined:
		return "declined: " + p.Reason
	}
}

type MemoryOrders struct{}

func (MemoryOrders) Find(id string) (Order, error[OrderNotFound]) {
	if id == "42" {
		return Order{ID: id, Total: 1999}
	}
	return OrderNotFound{ID: id}
}

type FakeGateway struct{ AuthID string }

func (g FakeGateway) Authorize(order Order) (Payment, error[GatewayDown]) {
	return Authorized{g.AuthID}
}

wire Live {
	Orders    = MemoryOrders{}
	Gateway   = FakeGateway{AuthID: "auth-7"}
	Scheduler = LiveScheduler{}
}

func main() uses Console {
	outcome := with(Live) { checkout("42") } catch {
	case OrderNotFound:
		"no such order"
	case GatewayDown, timeout.Expired:
		"gateway unavailable"
	}
	Console.Println(outcome)
}
```

What it shows:

- `checkout` names every failure in `error[...]` and every capability in `uses`. Leaving one out is S101 or S102.
- `try` escapes a failure; the `catch` without `try` in `main` must cover every error of the row (S103).
- `with(Live)` discharges the three capabilities for its block. `Live` binds providers, and the checker proves each one implements its capability with no wider row (S106).
- The union `Payment` has no zero value, and the type switch narrows it.
- The prototype lowers this to plain Go: one Go function per function, `if err != nil` returns, a type switch for `catch`, and one func literal for the timeout's child task.

## Proposed: automatic release

```go
func copyFile(src, dst string) error[NotFound | WriteFailed] uses FS {
	in := try FS.Open(src)
	out := try FS.Create(dst) // if this fails, in is still closed
	try io.Copy(out, in)      // lends out and in
}                             // out closed, then in
```

A type with `Close()` is a resource, and its owner scope closes it on every exit ([resources.md](../spec/resources.md)). There is no `defer` to write. Ownership moves by `return`, a provider field, `go` outside a structured lend, aggregate construction or assignment; an argument lends it, and a task bound after a resource borrows it under a structured lend.

## Proposed: HTML as functions

```go
func OrderRow(o Order) Node {
	return Tr(Class(statusClass(o.Status)),
		Td(Text(o.Member.Name)),
		Td(Int(o.Quantity.Wire())),
	)
}
```

The owner chose functions over markup syntax on 2026-10-26 ([stdlib.md](../spec/stdlib.md#html)).

## Proposed: laws by name

```go
func LawRoundTrip(q Quantity) bool {
	return ParseQuantity(q.Wire()) == q
}
```

A function named `LawX` that returns `bool` is a law, checked like a fuzz target; with `uses Store` it is checked against every provider wired for `Store` ([types.md](../spec/types.md#laws)). This is the `func LawX` spelling that [#170](https://github.com/cevr/effra/issues/170) asked for, and it supersedes the provisional `contract`/`law` spelling of the 2026-10-12 preview.

## What it does not claim

- No `ef` command checks this language yet. The parser and checker are [#195](https://github.com/cevr/effra/issues/195) and [#196](https://github.com/cevr/effra/issues/196).
- No performance result beyond the prototype's own receipt.
- Resources, tasks, generics, loops, machines, actors and the standard library are designed, not implemented.
