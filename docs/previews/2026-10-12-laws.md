## Tested candidate: a contract, its satisfaction and evidence

```rust
contract Order<T> {
    compare: fn(T, T) -> i64
    law reflexive(a: T) {
        compare(a, a) == 0
    }
    // a <= b and b <= c imply a <= c.
    law transitive(a: T, b: T, c: T) {
        if compare(a, b) <= 0 {
            if compare(b, c) <= 0 {
                compare(a, c) <= 0
            } else {
                true
            }
        } else {
            true
        }
    }
    // Any two values compare: a <= b or b <= a.
    law total(a: T, b: T) {
        if compare(a, b) <= 0 {
            true
        } else {
            compare(b, a) <= 0
        }
    }
}

User satisfies Order<User> cases 200 {
    compare = compareUsers
}

evidence SortedBy<S> by Order.compare

fn sortTrio(t: Trio) -> SortedBy<Trio, compareUsers> {
    mint SortedBy<Trio, compareUsers>(sortWith(t, compareUsers))
}

admit SortedBy<Trio, compareUsers> by sortedTrio

fn search(xs: SortedBy<Trio, compareUsers>, x: User) -> bool { … }
```

Omitted for length: the law `antisymmetric`, the records `User` and `Trio`, the functions `compareUsers`, `sortWith` and `sortedTrio`, and the body of `search` (marked `…`). All of them are ordinary declarations.

What it shows:

- A `contract` lists entries and laws. A law is a predicate over typed parameters, which the runner quantifies over generated values.
- A law is checked once, against the contract alone. `compare` is a value of type `fn(T, T) -> i64`, called positionally with two arguments, and `T` is an abstract type. So the law means the same thing for every satisfaction, whatever the bound function's parameter names or defaults are.
- `satisfies` binds a subject to the contract and states the case budget. `ef test --target both` runs every law on Go and on JavaScript from the same seeds and writes one receipt per target. A refuted law refuses `ef build`, and the refutation stands until an agreeing run on both targets over the same source, or a change to the source. An unreadable ledger is refused, never read as empty.
- `SortedBy<Trio, compareUsers>` is evidence. A function can mint it only when its index is a declaration that a satisfaction with passing laws binds. A function that requires it accepts nothing else. A host caller's value is checked again on entry by the declared admission check, `sortedTrio`.

## Proposed: the same contract in the provisional spelling

Effra has no `&&`, `||` or `!` today. The forms below assume `and`, `or` and `not` as boolean keywords, which is a #135 decision. The version above, with nested `if`, is the one that works today.

```rust
contract Order[T] {
    T.compare: fn(T, T) -> i64
    law reflexive(a: T) { T.compare(a, a) == 0 }
    law antisymmetric(a, b: T) {
        if T.compare(a, b) <= 0 and T.compare(b, a) <= 0 { T.compare(a, b) == 0 } else { true }
    }
    law transitive(a, b, c: T) {
        if T.compare(a, b) <= 0 and T.compare(b, c) <= 0 { T.compare(a, c) <= 0 } else { true }
    }
    law total(a, b: T) { T.compare(a, b) <= 0 or T.compare(b, a) <= 0 }
}

User satisfies Order cases 200

fn search(xs: SortedBy[Trio, User.compare], x: User) -> bool
```

An alternative for #135 to compare: a `when` guard clause.

```rust
law transitive(a, b, c: T) when T.compare(a, b) <= 0 and T.compare(b, c) <= 0 {
    T.compare(a, c) <= 0
}
```

- **Meaning of the guard.** A case whose guard is false is a vacuous pass. It counts against the budget and is never discarded and regenerated, so a guard cannot make a run loop or silently shrink its budget.
- **What the receipt adds.** The receipt records how many cases met the guard. A law whose guard almost never holds is therefore visible, not quietly tested.
- **Why it might win.** It reads as "for these inputs, this holds", with no `else { true }` branch.
- **What it costs.** One more clause in the law form.

`SortedBy[Trio, User.compare]` uses a declaration path, `User.compare`, as a type argument. That is how evidence names the comparator it rests on, and it is the spelling the owner should judge here.

## What this preview does not claim

- **Not admitted.** No construct here is admitted, and the prototype branch is never merged.
- **Spelling.** Neither spelling is final; #135 chooses it.
- **Not built:**
  - service, machine and runtime-contract laws;
  - generic and recursive generators;
  - conditional satisfaction;
  - the `when` guard;
  - `and`, `or` and `not`.
- **Tested is not proven.** A law that passes its cases is `tested`, never proven.
- **No performance result.** The cost measurements in laws.md §3 cover one workbox run and are not a performance claim about the language.
