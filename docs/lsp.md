# Language server

Start `ef lsp` over stdio, or `ef lsp --target js` to select the JavaScript target. Go is the default. Both input and output use LSP Content-Length framing with UTF-8 JSON bodies and CRLF headers. Stdout contains protocol messages only; terminal transport failures go to stderr and exit 1. Invalid CLI arguments exit 2.

The adapter advertises UTF-16 positions, full-document synchronization (`openClose: true`, `change: 1`), `hoverProvider`, `definitionProvider` and `documentFormattingProvider`. It implements initialize/initialized, shutdown/exit, textDocument/didOpen, didChange and didClose with versioned diagnostics, textDocument/hover, textDocument/definition and textDocument/formatting. Range and on-type formatting, completion, references, rename, code actions (including lint fixes) and workspace indexing are not advertised and receive method-not-found errors when requested.

Send initialize once, then the initialized notification before opening documents. Open requires `languageId: "effra"`, text, and an integer version. Changes require a strictly newer version and a nonempty list of full-text replacements; range and rangeLength fields are rejected, including null. All replacements are validated, then the final snapshot is checked. Duplicate opens, unknown changes/closes and invalid versions produce window/logMessage errors and preserve the accepted text. Close publishes an empty diagnostic list without a version and releases the buffer; reopen starts a new version sequence.

Documents use absolute local file URIs, such as `file:///home/me/project/main.ef`; paths with spaces use `%20`. Equivalent editor spellings are admitted, including escaped reserved or unreserved characters, upper/lowercase hex escapes, scheme case and `file:/absolute/path`. The decoded path is the retained document identity, so aliases cannot open separate authoritative buffers. The opening client's exact URI is kept in the compiler SourceSnapshot and echoed on every publication and close clearing, even when change/close arrives through another spelling. Reopen adopts the new opening URI. Disk-based CLI/MCP identities are unchanged.

The initial URI profile targets Linux: an empty authority, a valid UTF-8 decoded absolute path and a `.ef` extension. Authorities (including localhost), user information, queries, fragments, opaque paths, NUL, decoded dot segments and internal empty segments are refused. Encoded slash separators are refused rather than changing path segmentation; decoding happens once and does not collapse dot segments or resolve symlinks. Encoded URI length is limited to 4,096 bytes before parsing or retention, including change/close. This adapter limit is not a universal filesystem PATH_MAX claim. Admission never reads the file; new unsaved files are supported. Exact accepted text and opening URI form SourceSnapshot with origin `buffer`, and imports resolve from the decoded document directory.

Every accepted open/change runs the same compiler DiagnosticReport used by CLI/MCP. Publications retain the accepted document version, plain messages, stable codes, numeric severities and zero-based end-exclusive UTF-16 ranges. Errors, warnings and hints share the compiler projection, including CRLF, astral characters, combining marks and EOF positions. The adapter does not apply strict lint policy or silently suppress findings. A failed import, unavailable source location or report budget failure sends an explicit window/logMessage error with protocol code, opening URI and accepted version, and publishes no replacement diagnostic list. Error context and detail each have an 8 KiB UTF-8 budget; omitted detail states the exact omitted input byte count. This bounds operational log detail, not semantic findings: located reports remain complete or explicitly refused. Accepted text with unavailable analysis remains the current snapshot. Previous published diagnostics may remain visible until the next successful analysis or close; the error is not a claim that the latest text is clean.

## Hover and definition

Hover and definition answer from the checked result of the document's current accepted version. Each accepted open/change replaces that result together with the text; stale, invalid or refused changes keep the previous version's text and result, and close/shutdown release both. Requests are answered synchronously in receive order, so no answer can describe a version other than the current one. Both use the same producer-qualified selected-type query as `ef type FILE --offset N` and MCP `code.type` with `offset`, over identical text. The request's UTF-16 position is converted to that UTF-8 byte offset through the index diagnostics use: it names the code unit to its right, and a character beyond the line length is the line end before CR, LF or CRLF.

Only a name the checker resolved to a declaration has an answer: the selection must carry a `target` and its span must contain the position. Locals, parameters (including those of bodyless service operations, declared by the checked signature alone), pattern bindings, functions, service operations, provider methods, providers, services, records, enums, variants, fields, errors and module aliases qualify, both at the declaration name and at checked uses, including bundled module members. A call's argument label selects the parameter it binds: hover shows `parameter NAME: TYPE` and definition goes to the parameter name. Signature help is not implemented. Whitespace, comments, keywords, literals, operators, type annotations and other unsupported positions answer null, as does source without checked facts (diagnostics remain published). Hover returns `{contents: {kind: "plaintext", value}, range}` where `value` is the query's `presentation` and `range` is the selected token. Definition returns one Location in the opening document URI at the target's declaration name, only when the target has `locationAvailable: true`. Bundled and builtin declarations keep their identity in hover but answer null for definition; no imported source location is fabricated.

Hover and definition notifications receive an Invalid Request log. Missing position fields, negative or non-integer coordinates, an unopened document, a line beyond the document and a character between the two UTF-16 units of one astral character receive Invalid Params (-32602). A projection or tooling-limit refusal of the selected query receives Request Failed (-32803) with the opening URI and accepted version. Each refusal leaves the session and later requests intact. Arbitrary expression types remain available through the CLI and MCP queries.

## Document formatting

textDocument/formatting formats the document's current accepted text with the syntax-only formatter of `ef fmt` and MCP `code.format` (formatter identity `effra/formatter-6`); there is no editor-specific printer. Like those surfaces it needs valid syntax, not checked types: an ill-typed buffer or one with unresolved imports still formats, and the target does not matter. The `options` field is ignored, including tabSize and insertSpaces; the style is canonical. The buffer is formatted, never the disk file, which is neither read nor written.

The request captures the document's version and text, formats that text and refuses the result with Content Modified (-32801) unless the same version and text are still open afterwards. The text is compared because a reopen restarts the version sequence. Already formatted source answers `[]`. Changed source answers one TextEdit whose `newText` is the complete formatted document and whose range runs from line 0, character 0 to the end of the captured text in UTF-16 units, computed with the index diagnostics and navigation use; CRLF and astral characters are covered. Formatted output uses LF.

Unformattable syntax receives Request Failed (-32803) with the opening URI, the accepted version and the formatter's first syntax diagnostic, such as `cannot format: EF001: standalone carriage return is unsupported…` for a raw CR or EF002 for the legacy `()` no-value type and expression. Nothing is rewritten; the published diagnostics remain the full report. Formatted output over 512 KiB, or a response over the output budget, is also -32803 with no partial edit. A formatting notification receives an Invalid Request log; missing or invalid document identifiers and an unopened document receive Invalid Params (-32602). The session keeps serving after each refusal.

## Ordering and lifecycle

The session processes messages and analysis in receive order, without detached workers, debounce queues or stale result races. Each check completes before the next message is read. Cancellation for a completed or unknown request is a no-op; it cannot interrupt a synchronous document check. Compiler import loading keeps its existing per-subprocess 30-second deadline. Shutdown and EOF therefore wait for an in-progress check, and may also wait on a blocked client output stream. No stronger stop-latency guarantee is claimed. Shutdown releases all buffers before replying null; only exit is subsequently accepted. Exit after shutdown, or EOF after shutdown, exits 0; exit/EOF before shutdown exits 1.

| Admission boundary | Limit |
| --- | --- |
| Input body | 2 MiB, checked before body allocation |
| Headers | 8 KiB aggregate; 4 KiB reader line bound |
| Open documents | 32 |
| One document/replacement | 256 KiB of UTF-8 text |
| Retained document text | 2 MiB aggregate |
| Retained analysis | One checked result per open document, of its current accepted version |
| Hover text | 4,096-byte shared presentation budget with explicit `…` elision |
| Formatted document | 512 KiB of UTF-8 text; explicit refusal above the limit |
| Encoded document URI | 4,096 bytes before parsing/retention |
| Retained URI/path bytes | At most two 4,096-byte identities per document, plus fixed map/document metadata |
| Findings per report | 1,000; explicit refusal above the limit |
| Output | 2 MiB conservative pre-encoding budget and encoded-body bound |
| Operational log context/detail | 8 KiB each, plus bounded omission markers and protocol prefix |
| Request IDs | LSP signed 32-bit integers or strings; 256 encoded bytes |

The output budget charges JSON escape expansion and container/field overhead before serialization, so some messages smaller than 2 MiB may be refused. Reports are never silently truncated. Rejection logs and empty close publications fit the output budget for every admitted URI, so report-budget failures retain the session and permit close and queued follow-up. I/O/write failures remain terminal. Malformed JSON bodies receive Parse Error; valid nonobject JSON or invalid request shapes receive Invalid Request. These errors, invalid IDs and rejected document notifications retain framing and allow the next request. The current Go JSON decoder accepts case-insensitive struct field names and last duplicate keys. Shutdown requires omitted/null params and refuses `{}`; post-shutdown notifications other than exit produce an error log. Unpaired JSON UTF-16 escapes are rejected rather than replaced with different source text. Missing/duplicate/invalid Content-Length, unsupported content encoding, oversized headers/body and partial EOF are terminal framing failures because the next byte boundary cannot be trusted. Unknown notifications are ignored according to JSON-RPC; unsupported requests receive errors. Pre-initialize notifications are dropped, apart from exit.

`python3 scripts/lsp_smoke.py` exercises actual framed processes: split/coalesced frames, shared CLI/MCP diagnostic parity, Unicode ranges, unsaved buffers, version rejection, hover/definition parity with `ef type --offset` and MCP `code.type` on both targets over astral/CRLF source, null and refused positions, document formatting parity with `ef fmt --stdin` and MCP `code.format` over unsaved versioned buffers (astral/CRLF whole-document ranges, already formatted, empty, ill-typed, raw CR and legacy `()` sources), encoded editor URIs and alias close/reopen, module-relative imports, large operational detail, publication refusal, URI/text bounds, queued recovery and exit behavior. The large import control uses a real scratch module with unresolved imports and network/toolchain downloads disabled. `--review-case uri|operational|recovery|oversized|navigation|formatting` isolates the causal regression controls. The repository gate includes all checks; Go tests additionally cover byte/count release, exact omitted-byte count, output failure, ownership of accepted snapshots and refusal of a formatting result whose snapshot was changed, closed or reopened with other text before completion. The smoke disables Python bytecode writes, so manual runs leave no `scripts/__pycache__`.
