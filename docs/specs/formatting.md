## Syntax and preservation

Format `.ef` directly using the compiler lexer/parser and a comment-preserving syntax representation. Do not format generated Go or reconstruct source from semantic inspection. The current Program groups declarations by kind and loses interleaving; extend the shared syntax representation to retain lexical declaration order and comment attachment rather than printing those grouped slices. Keep the printer separate from checking and lowering.

Formatting requires valid supported syntax, not valid types, resolved imports, provided services or an entry point. It must not load host packages, execute effects, start custom lint packs, build a backend or contact the network. Syntax errors and unsupported syntax produce diagnostics with no replacement text or file writes. Source line endings support LF and CRLF; a standalone raw CR receives the shared lexer diagnostic rather than being silently rewritten or reinterpreted. Escaped `\r` in a string remains literal content. Initial whole-document formatting does not promise recovery or range formatting for incomplete syntax.

Preserve token spelling, declaration/import order, literal bytes, evaluation order, parentheses and comment contents. Change whitespace between tokens only; new grammar additions must extend the formatter and its acceptance corpus together. Output uses LF, four spaces per indentation level, no trailing whitespace outside comment/literal contents, and one final newline for nonempty output. Empty/whitespace-only files normalize to empty output. The first implementation publishes finite layout rules for each admitted construct: blocks, declarations, explicit `raises`/`uses` rows, matches, record/enum payloads, calls and fluent chains. Keep wrapping rules deterministic and tested; preserve deliberate blank separation while bounding runs of empty lines. No import organization, literal normalization, identifier rewriting or lint fixes in this command.

The initial syntax printer places top-level declarations and block statements on separate lines, uses one four-space indentation level per block, and keeps empty braces, `raises`/`uses` rows, call arguments and match patterns inline. Nonempty inline data, row and pattern braces use interior spaces (`{ field }`); empty braces remain `{}`. Fields and payload members in block braces are comma- or declaration-separated across lines; semicolons remain in the output and terminate ordinary statements. A next-line lint directive keeps all statements from its target source line together. Comments retain their token text and source-relative line separation, with runs of blank lines bounded for deterministic output.

When an author places a token boundary on a new physical line, the first token of a declaration, block statement, field, enum variant or match arm uses its enclosing block level. Other first tokens use one continuation level; each open parenthesis, nonempty inline brace or generic angle pair adds one continuation level, and its closer returns to the opener's level. Fluent, pipe (`|>`) and binary operators therefore indent their continuation lines, and multiline `raises`/`uses` rows, parameters, arguments and patterns follow the same rule. A block-style opener on its own line uses the enclosing block/continuation level and its body adds the block level, so the opener aligns with its closer. A pinned inline brace still contributes its continuation level to following lines. Indentation is derived from syntax roles and existing line breaks, never from incoming columns.

Formatting does not width-wrap or join author line breaks. Existing token-boundary line breaks remain, subject to structural block indentation and bounded blank runs. For every `ergo-lint-disable-next-line` line comment, including malformed or unused directives, the immediately following physical line keeps its token sequence and position relative to the comment; an empty or comment-only target remains so. The printer keeps a pinned target line together when ordinary layout would otherwise split it, including ordinary block comments on that line: a block comment followed by more source on its physical line never ends the line itself, so the following token's layout decides whether it breaks.

Comments require attachment evidence: leading documentation, trailing comments, comments inside argument/field lists, between closing braces and continuations, and EOF comments survive in order at their associated syntax. In particular, existing next-line lint directives are line-sensitive. Only `//` line comments are directives, in lint and formatter alike; a block comment spelling a directive is ordinary text, so moving it cannot activate a suppression. Preserve the same suppressed syntax and eligibility, including malformed/unused directive diagnostics; moving or wrapping source must not silently redirect or activate a suppression. Model directive attachment/line constraints explicitly, and return a diagnostic without output for a layout that cannot preserve them. A token-equivalence check alone cannot establish directive preservation.

The pure formatting result identifies formatter schema version, exact input-content digest, output digest and changed state; CLI/MCP adapter reports add the core formatter identity `ergo/formatter-16`, which admits the pipe operator `|>` (formatter-6 refuses it with `EFMT_SYNTAX`), contextual required-choice and scalar-default parameter syntax, generic enum parameters, explicit constructor applications, qualified enum patterns, the canonical `void` syntax, same-line block comments and the signed-64 multiplicative operators `*`, `/` and `%` alongside layers, scalar constant declarations, `machine` declarations (admitted from formatter-13) and typed endpoint and route-table `derive` declarations (`Http.endpoint(...) raises { Failure: status witness }`, `Http.routes(...)`, admitted from formatter-14), and machine decision forms (`enter e`, `stay e`, `ignore`, `reject`, `done e`, printed like `run` with one space and the operand on the word's line, admitted from formatter-16) while retaining wire schema 1 (formatter-10 refuses the multiplicative operators, formatter-12 refuses `machine` and the `derive` declarations, formatter-13 refuses the `derive` declarations, formatter-14 refuses `machine` and formatter-15 refuses decision forms, each with `EFMT_SYNTAX`). Angle roles come from the shared syntax parser: generic type arguments use delimiter indentation, while ordered comparisons keep binary spacing and never change block indentation. Likewise a binary `*` is a parser fact and keeps binary spacing, while a native pointer type `*T` stays attached. This producer identity is independently versioned from the wire schema and must be bumped whenever canonical formatting behavior or syntax admission changes; it is computed from the built producer identity and never by a Git query per request. It identifies syntax formatting only: semantic admission and checked parameter facts have their own versioned contract. A second formatting pass must be byte-identical. Share source-position conversion with semantic tooling where edits need UTF-16 ranges. The formatter shares syntax admission: the legacy `()` no-value type and expression are diagnosed with EF002 and never silently rewritten.

## Command and write behavior

`ergo fmt FILE...` formats explicit files in place; `ergo fmt --check FILE...` checks without writing and exits 1 for differences; `ergo fmt --stdin` formats stdin to stdout without a path mutation. Invalid invocation or syntax/operational failures exit 2 with distinct diagnostic codes. Support `--json` for file/check reports, with paths, input/output digests, changed/written state and failures; stdin formatted text and JSON reports are mutually exclusive. Human status goes to stderr when stdout carries source. No recursive discovery is required initially; diagnose directories rather than silently skipping them.

Use bounded regular-file admission before reading, including special-file rejection, deduplicate explicit paths only after resolving their intended OS paths, and reject symlinks for in-place writes with an actionable diagnostic. Preserve raw requested path components through OS resolution so symlinked ancestors and `..` address the file the kernel names. Multiple requested hardlink/inode aliases are rejected; one selected hardlink is replaced through an atomic rename and therefore splits from unlisted links. A read-only regular file in a writable directory may be replaced while preserving permission and special mode bits. Compute all results before any writes so parse/validation failures do not partially format a file set. Recheck the exact original contents before replacing each file, and use same-directory atomic replacement with owned temporary-file cleanup. Report a concurrent edit as stale instead of overwriting it. Multi-file writes are not an atomic transaction: report any earlier successful writes if a later I/O or stale-source failure occurs. Never report success for a partial write. Do not claim hostile concurrent filesystem mutation or directory-fsync durability; these are cooperative workspace guards.

The CLI admits at most 100 files, 2 MiB per file and 8 MiB aggregate input, with 4 MiB per file and 16 MiB aggregate formatted output. MCP `code.format` admits 2 MiB source and 4 MiB formatted output, and its newline frame and encoded response each allow 16 MiB before the terminal LF. Bounded formatting responses preserve validated scalar JSON-RPC IDs without re-encoding their raw representation; other response fields use bounded JSON encoding; a successful/tool-error overflow uses compact `-32000`, while an argument/protocol error keeps its original code and ID. Formatter source must be valid UTF-8; invalid bytes produce lexical EF001 with their first invalid byte span and no replacement. Human status goes to stderr, structured file reports go to stdout when `--json` is selected, and failures use the documented `EFMT_*` codes in [tooling](../tooling.md#formatter-limits-and-filesystem-policy).

## Editor and agent adapters

MCP `code.format` returns formatted content or a bounded whole-document edit preview plus input digest and explicit source origin. It never writes source. Accept an explicit buffer or a guarded disk snapshot and reject a mismatched expected digest. Limits fail explicitly; no truncated replacement text. The caller applies the edit only to that same snapshot.

The [language server](semantic-tooling.md) supports `textDocument/formatting` using its current versioned buffer and the same formatter. Advertise document formatting only when implemented. Capture document version/content and reject a result invalidated during computation. Return no edits for already formatted source, a whole-document UTF-16 edit for changed valid syntax, and an explicit request error for unformattable syntax. Editor indentation options do not override the canonical style. Range/on-type formatting and lint code actions remain separate future contracts.

## 2026 edition

Status: implemented by [#195](https://github.com/cevr/ergo/issues/195), 2026-10-27. A source of the [2026 edition](editions.md) formats with `ergo-2026/formatter-1` (`internal/sketch/format`, `format.Identity`), a separate formatter over the 2026 parser `internal/sketch/syntax`. It never runs on a legacy source, and the legacy formatter never runs on a 2026 source.

- **Layout.** gofmt's layout model for every construct Go has: tabs for indentation; column alignment of struct fields, trailing comments, keys of multi-line composite literals, the `=` of wire entries and `var` groups, and machine entries (an alignment section ends where a cell's width differs from the geometric mean of its section by a factor of 2.5 or more, unless both it and the previous cell are at most 40 wide: go/printer's rule for keyed literals, applied to every column, so one long name does not pad its neighbours. An empty cell, such as the missing type of an inferred `var` declaration, stays in a section only while the section's widest cell is at most 40, and a section that holds an empty cell ends before a cell wider than 40. So `a int = 1`, `b = 2`, `ccccc string = "x"` align as gofmt aligns them, and no run of empty cells carries a long type's width to its neighbours: the padding of an empty cell is at most 41 columns. The section bound: once a section holds a cell wider than 40, every non-empty cell in it stays within a factor of 2.5 of its widest cell, so a slowly tapering run of names cannot carry a long width to short cells. A cell's padding is therefore at most 41 columns or less than 1.5 times its own width plus one, and the formatted output is linear in the input for every input); a bracketed list (parameters, arguments, elements) indents its items at its first line break, as go/printer does, so an item that spans lines before that break, such as a function literal or a nested parameter list, keeps the level the list started at; grouped names that the author breaks across lines (`x,` / `y int`) add their own continuation level only when their list has not yet indented, as gofmt indents them; no width wrapping; each gap between tokens keeps "line break or not"; runs of blank lines collapse to one; no leading blank lines; one final newline; an explicit `;` between statements becomes a line break, and a line break between the parts of an `if`, `switch` or `for` header becomes `; ` (gofmt); the explicit `;` of an empty labelled statement stays on its own line; a comma before a closer on the same line is removed. Binary expressions are spaced by precedence as gofmt spaces them. Tokens are otherwise kept: no import sorting, no parenthesis removal, no rewriting.
- **Effra constructs.** `error[A | B]` stays inline; `needs A, B` follows the results; a wire header keeps `provides A, B` before `needs C, D` on the `wire` line; a trailing block opens on the call's line; `catch` arms are laid out as switch clauses; `case (A, B), (C, D):`; machine and wire bodies are laid out like a struct body. A statement block inside a function is always multi-line; a function body that is one line in the source stays one line.
- **Comments.** Every comment is kept, in order, between the same two tokens: a comma, a `|`, the `]` of an array type or the `.` of a selector is printed at its source position, so a comment never crosses it (gofmt moves some of these comments; it can, because it never prints a closer after a line comment). After a block comment on the same line there is no blank before `,`, nor before `)` or `]` unless the comment follows the opener (go/printer). An own-line comment takes the indentation of the block or clause body that holds it, never its source column (a deviation from gofmt, which keeps some source columns). An own-line comment between a clause's last statement and the next `case` or `default` belongs to the next clause when a blank line separates it from the statement above, and to the previous clause body otherwise. A `//ef:go` directive stays attached to the declaration below it. A raw string that spans lines is never re-indented.
- **Surfaces.** `ergo fmt FILE`, MCP `code.format` with `file` and LSP `textDocument/formatting` use it for a 2026 file, with the legacy limits, `EFMT_*` codes, write and stale-source rules. One CLI request may mix editions: each file report carries `formatterVersion`, the identity of the formatter that formatted it, and the report's top-level `formatterVersion` stays the legacy identity. MCP reports the identity in `structuredContent.formatterVersion`. A syntax error is `EFMT_SYNTAX` on the CLI, with the message `source cannot be formatted: S001 at LINE:COLUMN: ...` and the diagnostic in the JSON failure; MCP returns the same text as the tool error, and the LSP answers Request Failed naming `S001`. `ergo fmt --stdin` and `code.format` with `source` have no directory and stay legacy. The output bound is checked from the laid-out cells before the text is built, so a refused input never allocates its output. The LSP resolves the edition again after formatting and refuses the edits (EF145, or the resolution's EF144 or EF146) when it changed.
- **Properties.** The tests in `internal/sketch/format` check, on the [conformance corpus](../spec/README.md), every fenced example of `docs/spec/` and the grammar fixtures: the output parses; formatting the output changes nothing; the tree is the same, without positions and comments; the interleaved sequence of tokens and comments is kept (modulo semicolons and a comma before a closer); five whitespace perturbations of each input format to the same text. `TestCommentsAtEveryBoundary` inserts four kinds of comment before every token of nested-chain programs, the grammar fixtures, the spec fences and every seventh token of the corpus (10 913 variants), and checks the same properties. `FuzzFormat` checks them on generated inputs.

## Acceptance and delivery

1. Shared syntax retention and pure formatter: real-source goldens for every admitted construct and all comment positions; idempotence; parse-tree equivalence ignoring layout spans; exact token/literal/order preservation; unchanged directive targets and suppression outcomes, including multiple expressions on a line and malformed directives. Cover Unicode, CRLF, EOF, empty files, deep/numerous constructs and syntax errors. Format valid syntax with unresolved types/imports while proving no package loader or checker runs. Record isolated formatting time/allocation receipts, with source size and toolchain; no unmeasured speed claim.
2. CLI and MCP: real-process tests for check/write/stdin/JSON, mixed valid and invalid file sets, duplicate paths, special files, symlinks, permissions, concurrent changes, size/output limits and unchanged-file behavior. Compare shared output and digests across surfaces. This batch gates the adapters with an explicit process smoke test; adopt canonical formatting for authored `.ef` examples in a separate reviewable mechanical commit, excluding intentionally malformed and legacy-diagnostic fixtures and pinned upstream bytes. The maintained authored-source selection lives in `scripts/authored_examples.txt`; new authored examples must be listed there, and the gate diagnoses any listed path that is missing. The check uses syntax-only `ergo fmt --check` and does not require successful typechecking.

## Prior art

Go1.27.0 `src/go/format/format.go` separates canonical printing from type resolution and preserves comments through parser/printer structures; its version warning motivates explicit formatter identity. Effra initially preserves import order and literal spelling rather than adopting Go's normalization choices. Gleam source at `52e735c82d42811dd08d29d5508f564da081fd7d`, `compiler-cli/src/format.rs`, shows one shared printer serving stdin, file writes and check mode, with formatting computed before writes. These are source comparisons, not inherited preservation guarantees.

Elixir's formatter at `91ee75bb` is also syntax-only: it parses with comments and reprints (`lib/elixir/lib/code.ex:L1119-L1131`), and `mix format --check-formatted` serves CI (`lib/mix/lib/mix/tasks/format.ex:L68-L79`). It differs where Effra is stricter. Its `line_length` is a configurable target (default 98) (`code.ex:L748-L751`), and comments are preserved "in most cases", with trailing comments moved to the previous line (`code.ex:L1039-L1060`). Effra rejects configurable layout and width wrapping, and refuses a layout that would move a line-sensitive directive. MoonBit ships `moon fmt` (`next/toolchain/moon/commands.md:L40-L68` at docs `8d9f3ba2`); its layout rules were not compared. Pins are in [PRIOR_ART](../../PRIOR_ART.md#standing-comparison-languages-elixir-with-erlangotp-and-moonbit-2026-10-09).
