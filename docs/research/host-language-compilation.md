# Host-language compilation comparisons

Source review, 2026-10-06. The owner requested Gleam, ReScript and TypeScript alongside Go and Borgo as prior art. These are source/test inspection receipts, not fresh runs of upstream suites or comparative speed measurements. Revisions are pinned in [PRIOR_ARTS](../../PRIOR_ARTS.md).

## What to adopt

| Concern | Observed implementation | Effra decision and executable acceptance |
| --- | --- | --- |
| Target capabilities | Gleam's `compiler-core/src/javascript/tests/externals.rs` covers target-specific external functions, both-target implementations, fallback bodies, invalid external identifiers and generated declarations. | Keep portable contracts distinct from target implementations. A wrong-target call must diagnose at the original source; a portable service with two valid providers must run on both targets. Do not infer a foreign implementation's behavior from its declaration. |
| Host-facing declarations | Gleam's `javascript/typescript.rs` projects declarations from its typed AST. ReScript's `tests/gentype_tests/typescript-react-example/src/Variants.gen.tsx` exposes tagged variants, and `Opaque.gen.tsx` represents opaque identity. Their generated forms are not runtime input validation. | Project exports from the canonical checked contract. Test a real TS consumer, including payload variants and opaque host values. Preserve effect rows in JS exports and reject unsupported representations rather than erasing them to `any`. Stable nominal package identity must precede cross-package exports. |
| Foreign call shape | ReScript's `tests/tests/src/ffi_test.res` explicitly binds constructors, getters/setters, methods and indexed access. This documents the distinct host calling conventions the compiler handles. | Automatically ingest supported host declarations instead of copying those signatures into every application. Keep supplemental behavior contracts for cancellation, partial results, mutation and retained callbacks. Diagnostics identify the unsupported member and the needed representation; they must not silently invent adapters. |
| Incremental checking | Gleam's `build/module_loader.rs` uses cached metadata, source fingerprints, code-generation availability and incomplete LSP-state tracking. Its tests distinguish a reusable check result from a cache missing code generation. | Version interface, check and emitted artifacts separately. A previous check-only run cannot satisfy a build. Test edits, recovered failures, missing output and target changes rather than measuring only a no-op rebuild. |
| Public interface changes | ReScript's `rewatch/src/build/compile.rs` compares compiled interface digests and avoids dirtying downstream modules when the interface is unchanged. `rewatch/tests/watch/07-changed-interface-after-failed-implementation.sh` tests retaining dirty dependents across a failed implementation and later recovery. | Preserve public-interface fingerprints independently from private implementation changes. A failed build cannot publish a successful semantic revision. Test private edit, public edit, dependency edit, failed public edit and recovery; record rechecked modules and stage costs. |
| Runtime source locations | ReScript's `compiler/core/js_source_map.ml` carries locations through its JS representation to the printer, converts UTF-8 source columns to UTF-16 map columns, and emits per-output maps. `tests/build_tests/source_map/input.js` checks actual Node stack traces and non-ASCII locations. Gleam also has generated-map tests in `javascript/tests/sourcemaps.rs`. | Carry source anchors through lowering instead of reconstructing them from generated strings. Assert a thrown defect maps to the correct `.ef` span, including non-ASCII text and generated helper frames. JS source maps and Go source-location policy need separate receipts. |
| Mapped foreign source | TypeScript's `tsc/internal/contentmapper` transforms otherwise unsupported input into virtual TypeScript and maps diagnostics. The original [content-mapper PR](https://github.com/microsoft/typescript-go/pull/4712) documents the protocol; current source is in the main TypeScript repository. | An optional Effra mapper may provide JS editor integration. The Effra semantic model remains the authority for effects, requirements, ownership and machine graphs. A mapped TS program cannot prove those guarantees, and a Go-only build must not start TypeScript or a mapper. |
| Cache configuration identity | TypeScript's `contentmapper.Mapper.TransformIdentity` incorporates mapper identity, mapper options and declared compiler options. `execute/incremental/buildinfo_contentmapper_test.go` checks static/dynamic identity changes and identity failures. | Cache keys include compiler/interface versions, target, dependency summaries and relevant adapter/configuration identity. A changed mapper configuration invalidates projections even when `.ef` bytes are unchanged. Failure to obtain identity cannot silently reuse a successful result. |

## Representation is an explicit boundary

The adoption goal is convenient host reuse, not an assumption that all host representations coincide. A portable closed enum, a Go interface implementation, a TS discriminated union and JSON bytes have different obligations. Preserve host-native named values where supported; derive or select codecs when crossing a data boundary. Avoid routing ordinary in-process calls through JSON merely to unify backends.

Borrow TypeScript's declaration-led integration and gradual adoption, while keeping Effra's checked contracts distinct from imported assertions. A `.d.ts` declaration supplies a callable shape, not evidence of runtime validation, cancellation or completed cleanup. A content mapper supplies source correspondence, not soundness. Representation-specific adaptations and trusted behavior must remain visible in CLI/MCP.

## Delivery boundaries

The current primitive Go importer remains supported. The immediate native-interface task establishes canonical function/row contracts and versioned bundled interfaces. Its acceptance must leave room for host-qualified identity, but it must not claim the full TS importer, public package system, source maps or incremental build system is already implemented.

Follow-on work has three finite units: (1) host declaration projections and checked callable representation, with real Go/TS consumer fixtures; (2) source maps and structured runtime locations; (3) package interface caching with invalidation/recovery tests and cold/warm/edit measurements. Complete the native codec/server slice first so these mechanisms have real consumers. These carried units remain visible in Wayfinder instead of becoming implied capabilities.

No compile-speed ranking follows from this review. Compare the same program and cache regime with exact compiler/backend versions, separately reporting frontend, import, emission, host compile and link times.
