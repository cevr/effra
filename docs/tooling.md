# Developer tooling

Every `ergo` command reads one `.ef` source through one front end, `internal/sketchfront`, which checks, formats and builds the language of [`docs/spec/`](spec/README.md). There is no manifest and no edition. One table in `cmd/ergo/commands.go` gives every command word one fate, and dispatch, `ergo --help` and the stubs read only that table.

| Command | Fate | Output and exit |
| --- | --- | --- |
| `check FILE [--target go]` | Runs | The check envelope as JSON; exit 0 when the source checks, 1 when it does not |
| `diagnostics FILE [--strict] [--json] [--target go]` | Runs | One finding per line, or the diagnostic report as JSON; exit 0 when policy passes, 1 when it fails, 2 for an invalid invocation |
| `build FILE [-o PATH] [--target go]` | Runs | Builds a native executable, `dist/NAME` by default, and prints its path; a source that does not check prints its check envelope and builds nothing |
| `run FILE [--target go]` | Runs | Builds, then runs the program; SIGINT and SIGTERM are forwarded and the program's exit status passes through; a program that a forwarded signal ends exits 128 plus the signal number (130 for SIGINT, 143 for SIGTERM), with no message of `ergo`'s own |
| `fmt FILE... [--check] [--json]`, `fmt --stdin` | Runs | Canonical formatting; files are replaced atomically |
| `test FILE` | Not available yet | `not available yet; lowering adds it (#196)`, exit 1 |
| `edition` | Removed | `removed in v1; there is one language and no editions (#205)`, exit 1 |
| `lint`, `lint rules`, `lint test`, `lint receipt` | Removed | `removed in v1; linting returns on the new checker (#203)`, exit 1 |
| `inspect`, `explain`, `query`, `type`, `graph` | Removed | `removed in v1; semantic tooling returns on the new front end (#203)`, exit 1 |
| `lsp`, `mcp` | Dark | `unavailable until ported to the new front end (#203)`, exit 1 ([language server](lsp.md), [MCP](mcp.md)) |

A command that does not run prints one line to stderr, `ergo NAME: ` and the text in the table, prints nothing to stdout and exits 1, before it reads its arguments: `ergo inspect --help` prints the stub too. `ergo --help` lists only the commands that run and `ergo test`. An unknown word is `unknown command X; use ergo --help`, exit 1. The [retirement record](receipts/retire-ef.md) lists what [#203](https://github.com/cevr/ergo/issues/203) restores.

Go is the only target. `--target` accepts only `go`, the default; any other value is the EF110 refusal. `--strict` and `--json` belong to `diagnostics`, and `-o` to `build`; any other option is unknown: exit 2 for `diagnostics` and `fmt`, exit 1 for `check`, `build` and `run`.

## Source admission

A command locates its source once (`internal/receipt.LocateSource`): the spelling is made absolute, which applies a `..` to the spelled name, and the links of that admitted path are then resolved. Diagnostics and `//line` directives name the admitted path; the bytes come from one non-blocking open of the resolved file (`internal/source.Open`), which refuses a directory, a FIFO or any other file that is not regular, so a FIFO swapped in after a stat never blocks. A source must have the `.ef` extension. An `ergo.json` beside a source is ignored.

## Check envelope

`ergo check` prints one JSON object: `schemaVersion` (10), `checked`, `target`, `revision` (a SHA-256 digest that identifies the source), `diagnostics` (at most 100, each with `code`, `message` and a UTF-8 byte `span` with one-based line and column), `diagnosticsTruncated`, the `producer` that made the facts, and the `snapshot` that binds the schema, revision, target and producer together. Producer identity follows the executing artifact: its digest when the executable can be read, and a process-scoped qualifier when it cannot. `ergo build` and `ergo run` acquire a producer identity only when they refuse a source. The emission cache keys on its own digest of the compiler executable, which needs no producer identity ([runtime.md](spec/runtime.md), Host and lowering notes).

## Diagnostic reports

`ergo diagnostics --json` prints the report (`schemaVersion` 2). Its `source` identifies the file with a canonical escaped `file:` URI and the origin `disk`. It includes the source `revision`, the `target`, the `checked` state, the `strict` policy, `policyPassed`, exact `totalCounts` and `returnedCount`, `truncated`, the `producer` and `snapshot` of the check envelope, and the findings. Every finding keeps its UTF-8 byte `span` and reports `code`, `origin`, `severity` (`error`, `warning`, `information` or `hint`) and `message`. A finding with a source location also has a zero-based UTF-16 `lsp.range`; `locationAvailable` is false for a finding without one, such as the unsupported target refusal.

Errors always fail policy. Strict mode changes only the policy decision for warnings; it does not change a finding's severity. Text output prints one finding per line with one-based UTF-16 lines and columns. Exit 0 means policy passed. Exit 1 with a JSON report on stdout means the source failed policy; exit 1 without a report is an operational failure, explained on stderr. `ergo diagnostics --help` documents the same.

## Formatter

`ergo fmt` formats with the one formatter and reports one formatter identity, at the top level and per file. `--stdin` writes only formatted source to stdout. Human file statuses and operational errors go to stderr. File `--json` and `--check --json` reports use stdout and keep stderr empty; `--stdin` with `--json` is an invocation error. Exit 0 means formatting completed (or the check found no differences), exit 1 means the check found differences, and exit 2 means an invocation, syntax, I/O, stale-source or limit failure.

| Boundary | Limit |
| --- | ---: |
| File count | 100 files |
| Input per file | 2 MiB |
| Input per request | 8 MiB |
| Formatted output per file | 4 MiB |
| Formatted output per request | 16 MiB |

Completed file entries include `path`, `requestedPaths`, digests, `changed`, `written` and `completed`; a failed entry never receives a successful human status. The stable operational codes are:

| Code | Meaning |
| --- | --- |
| `EFMT_INVOCATION` | Incompatible options, missing input, or file-count admission failure |
| `EFMT_PATH` | Empty, non-`.ef`, or otherwise invalid path |
| `EFMT_READ` | The source could not be admitted or read |
| `EFMT_SYMLINK` | A mutating request named a symlink leaf |
| `EFMT_SPECIAL_FILE` | A directory, FIFO or other non-regular source |
| `EFMT_INPUT_LIMIT` | A per-file or aggregate input budget is exceeded |
| `EFMT_OUTPUT_LIMIT` | A per-file or aggregate formatted-output budget is exceeded |
| `EFMT_SYNTAX` | The source does not parse |
| `EFMT_FORMAT` | Any other formatter failure |
| `EFMT_ALIAS` | Several requested names resolve to one underlying inode |
| `EFMT_STALE` | The source identity or exact bytes changed before replacement |
| `EFMT_WRITE` | A temporary-file, permission, rename or other replacement failure |

Mutating paths keep the requested display spelling while the operating system resolves ancestor symlinks and `..` components. The leaf must stay regular and not a symlink at each replacement check. Lexical spellings that resolve to the same path are deduplicated; distinct hardlink or inode aliases in one request are rejected. A requested hardlink is replaced through an atomic same-directory rename, so that directory entry splits from unlisted hardlinks. A read-only regular file may be replaced when its directory is writable, and its permission, setuid, setgid and sticky bits are kept. These cooperative checks do not claim hostile-filesystem race protection or directory-fsync durability.

The formatter does not refuse invalid UTF-8. It formats such a source and writes the invalid bytes of comments and string literals back unchanged; an invalid byte where an identifier may start is the parse error S001, `EFMT_SYNTAX`. The earlier front end refused every invalid byte with EF001.

## Gate prerequisites

The gate needs Go and Git. It needs no Node, Bun, TypeScript or Effect installation: since 2026-10-26 Go is the only target.

## Merge gate

`scripts/gate.sh` runs `go run ./scripts/gate`, a small Go runner that owns the check graph ([design and measurements](research/gate-throughput.md)). Every check is a step with declared dependencies. Independent steps run concurrently. Each step's output is printed whole, in declaration order. A failing step fails the gate and blocks only the steps that depend on it. `--list` prints every step and its command, `--no-cache` reruns everything, and `--record-durations` re-measures the slow Go packages.

- **Go tests** rely on Go's own test cache, which stays authoritative. `cmd/ergo` is split into processes using the measured durations in `scripts/gate/durations.json`. Every shard but the last selects tests by exact name; the last shard skips exactly the names the others selected. So the union of shards covers every test, including tests added since the durations were last recorded. A stale durations file costs wall time, never coverage.
- **Go test inputs are observed.** Go's test cache keys a result on the files and variables the test process reads through package `os`. It cannot see what a child process reads: git, `sh`, a C compiler, or a `go build` that a test or the code under test starts. So every test package's `TestMain` calls `testinputs.Main(m)` (or `testinputs.MainFunc` when it prepares the test process). Main runs the test binary again as a child. The child installs a seccomp filter with a user-notification listener, writes the listener's number on a socket to the parent, which takes the listener itself with `pidfd_getfd` (Linux 5.6). Sending the listener by `SCM_RIGHTS` would need a `sendmsg` the filter lets through unnotified, since no one serves the listener before it arrives, and a process forked before that gap closed could use it to pass a socket address by the observer; taken this way, the filter has one rule for every process and no exception. `pidfd_getfd` needs the access ptrace would (`PTRACE_MODE_ATTACH_REALCREDS`: the same user, a dumpable child, and Yama's consent, which `ptrace_scope` 0 and 1 give a parent). The parent first takes a descriptor the child holds from its start, its end of the socket, and tells the child whether to install the filter at all, so a host that refuses (`ptrace_scope` 2 or 3) runs the tests unfiltered and refuses the result instead of leaving the child waiting on a listener no one serves. This workbox has no Yama (kernel 6.12, LSMs capability, landlock and selinux, not enforcing), and the take succeeds. Then the child runs the test binary again by exec: the filter survives exec, so every package initializer runs observed, including those Go ran before testinputs' own. The filter suspends every open, stat-like lookup, write that depends on what exists (`mkdir`, `unlink`, `rename`, `link`, `symlink`, `chmod`, `setxattr` and the like), `chdir`, exec, and `connect`, `bind`, `sendto`, `sendmsg` and `sendmmsg` with an address, the child and its descendants make until the parent has read the call's path; the call then continues unchanged. The test process trusts the observer's variables (`ERGO_TESTINPUTS_LISTENER`, `ERGO_TESTINPUTS_FILTERED`) only once it proves the observer exists: the descriptor a variable names must be a socket whose peer is its parent (`SO_PEERCRED`), kept open across the exec, and the exec'd process must run under a seccomp filter. A variable inherited from a shell or another runner fails that proof, and the result is refused as unobserved. When the child exits, the parent appends to Go's test log:
  - `open` for a file read or a program run, with the `#!` interpreters it names, and for a directory listed, which cmd/go keys on every entry's name and metadata;
  - `stat` for every other lookup, failed ones included, so a file added later is an input, for a directory changed to, and for the path of an AF_UNIX socket connected to, bound or sent to (an abstract or unnamed address names no file); a path both read and looked up gets both lines, since `open` does not look at a link itself. After the run, every link inside the root on the way to a recorded path gets a `stat` too: cmd/go rechecks an `open` path by what it leads to, and a retargeted link may lead to a file with the same size and time;
  - `getenv` for every variable in the environment of every program run, plus `ERGO_TOOL_VERSIONS` whenever a program ran.

  A path outside the module root is dropped, because cmd/go never rechecks such paths, unless its lookup reaches the root through a link. The parent resolves it one component at a time, as the kernel does, and records the rest of the path from the point it enters the root, unresolved: a link inside the root that is later retargeted, or a directory there that is missing now and added later, then changes the key. Nothing the observed processes can change is remembered between calls; only what a lookup finds in a directory that another user owns and this user cannot write, on a path of such directories, is (never when the tests run as root, with real, effective, saved or file-system user or group IDs that differ, or with `CAP_CHOWN`, `CAP_DAC_OVERRIDE`, `CAP_FOWNER`, `CAP_SETGID`, `CAP_SETUID` or `CAP_SYS_ADMIN` permitted or effective). A name relative to a working directory or a directory descriptor reached through a link inside the root (`cd dirs/current`; `openat` on, or `fchdir` to, a directory opened as `dirs/current`, with or without `O_DIRECTORY`) is recorded under the link as well as under the directory. fabricate.py tracks working directories per process and copies one to a child at `clone`, `fork` and `vfork`, which strace reports with the child's pid. A seccomp notification comes before the call, so the observer never learns a child's pid at the fork, and by the child's first lookup its parent may have exited and the child been reparented. So each link inside the root that a `chdir`, or the open of a directory (judged by the file the path leads to), crossed is remembered by the directory it leads to, for the whole run, and any process whose working directory, or a descriptor it names a path relative to, is that directory records its relative names under each such link too: a reparented child, a descriptor passed to another process and an `fchdir` (which is not notified) are covered, and a process that reached the directory another way gets an extra entry, which can only cause a rerun. A read open in the root costs one more `stat` for this, and a directory one more open and `readlink`. `/proc/self/cwd/…`, `/proc/<pid>/root/…`, `/proc/self/fd/<n>/…` and `/dev/fd/<n>/…` are read through the caller's links. Other paths under `/proc`, `/dev` and `/sys` are skipped, judged after `..` is resolved, so `/proc/../<root>/x` is recorded. This happens in Main, so `go test` run by hand observes exactly as the gate does. `internal/testinputs/guard` fails any test package without a `TestMain` that calls Main on every platform; `ERGO_TESTINPUTS_GENERATE=1 go test ./internal/testinputs/guard` writes the missing ones. It finds test packages under any build tags by walking the tree as `./...` does (skipping `testdata`, names starting with `.` or `_`, nested modules and links to directories), with ordinary directory reads that Main records, so a new package, tracked or not, in any clone, worktree or Rift, changes a listing and reruns it. `internal/testinputs` itself is exempt: its end-to-end cases run observed fixture binaries, and observation does not nest (a listener installed below another hides the calls it takes from the outer one). Those cases prime Go's cache, edit what only a subprocess read, and require a rerun, each beside a control with a plain `TestMain` that must replay its stale result.
- **Unobserved results are never cached.** When Main cannot observe, it leaves the test log without its final newline and prints `testinputs: result not cacheable, inputs unobserved: <reason>`; cmd/go then refuses to cache the result (`saveOutput` in `cmd/go/internal/test`), so the package reruns every time instead of replaying a result keyed on a partial list. That happens on another operating system or architecture (observation needs Linux 5.7 or later on amd64 or arm64), when seccomp is refused, when the parent may not take a descriptor from the child (`pidfd_getfd` refused: Yama's `ptrace_scope` 2 or 3, an undumpable test binary), when the parent cannot read a suspended call's memory that the kernel can (`process_vm_readv` fails other than with `EFAULT`, as for a process that made itself undumpable), when a process makes a call that would hide later accesses (`chroot`, `pivot_root`, `unshare`, `setns`, `mount`, `umount2`, the new mount API (`open_tree`, `move_mount`, `fsopen`, `fsmount`, `fspick`, `mount_setattr`), a namespace-creating `clone` or `clone3`, `open_by_handle_at`, `fanotify_mark`, `quotactl`, `quotactl_fd`, `bpf` (which watch or open paths without a lookup the observer sees), its own seccomp listener, a call of another ABI, a system call numbered above the last one of Linux 6.12, which the observer cannot classify), for a path or variable name that holds a newline, which the log cannot carry, when an observer variable is set without an observer behind it, and when the log cannot be marked (the test then fails, since cmd/go never caches a failure). `io_uring_setup` fails with `ENOSYS` under observation, because a ring opens files without system calls; a program that uses one must fall back to ordinary calls.
- **What observation does not key.**
  - Files outside the module root: tool installations, `~/.gitconfig`, user caches, system libraries. `ERGO_TOOL_VERSIONS` stands for the installations (below); tests that run git isolate it from user configuration (`GIT_CONFIG_GLOBAL`, `GIT_CONFIG_NOSYSTEM`). In a linked worktree or a Rift, `.git` is a file naming metadata outside the root, so the HEAD, index and objects a test's git reads there are not keyed either.
  - A variable that was unset when a result was cached, read by a program the test runs. A program's lookup of a variable is a library call, not a system call, so it leaves no trace, and cmd/go's log cannot say "every variable, present or not". The gate closes this for its own runs: a Go test step receives only the variables `internal/testinputs/testenv` names, whose values join `ERGO_TOOL_VERSIONS`, and the gate log prints the list. `go test` run by hand passes the caller's whole environment, so exporting a variable after a cached run can replay a result the variable would change; run `go test -count=1`, or use the gate. Every variable a started program receives is keyed, so running the tests by hand from a shell with a different environment reruns the packages that start programs.
  - Extended attributes: cmd/go's log has no entry for them, and changing one changes no modification time. `setxattr` and `removexattr` are recorded as lookups of their paths.
  - Two changes of a file inside one clock tick with the same size, and a change made with the old modification time restored (`touch -r`, `tar -x`, `rsync -a`, `cp -a`), for files: cmd/go rechecks a file by size, mode and modification time, not content. A directory listed is rechecked by its entries, so an entry added under a restored directory time is still seen.
  - A relative `#!` interpreter, which the kernel resolves against the working directory, and the dynamic loader an ELF program names (`PT_INTERP`). Every program here names an absolute interpreter and the system loader, both outside the root.
  - Races inside one run: a file the observed tree changes between the parent's lookup and the call it suspended, and a thread that changes the shared working directory, or reuses a descriptor number, while another thread's call waits. A link a `chdir` or a directory's open crossed is matched to working directories and descriptors by the directory it led to when the call was notified, which a link retargeted in between changes.
  - A runner that fakes the observer on purpose. The test process proves only that its parent created the socket it inherited and that some seccomp filter is installed (`Seccomp: 2` in `/proc/self/status`), not that the filter is this observer's: a `go test -exec` wrapper that makes a socket pair, sets `ERGO_TESTINPUTS_FILTERED` and runs the binary under an unrelated filter makes the tests run unobserved while believing they are observed. Any check the test process could make, such as a nonce the parent echoes, is one more message such a wrapper can answer, so the proof is aimed at what happens by accident (a variable inherited from a shell, a runner or a nested test), which it catches, and a deliberate wrapper is out of scope, as one that rewrites the test log is.
  - Processes a test leaves running after it exits: once the observing parent exits, their filtered calls fail with `ENOSYS`. The filter sets `no_new_privs`, so a setuid program does not gain privileges under a test.
- **What observation costs.** An observed call waits for the parent: a stat takes about 15 µs instead of 1.4 µs with synchronous wake-up (Linux 6.6 and later), most of it the kernel's round trip. The go command makes most of the calls: on every run it stats each standard-library source it builds on, and a seccomp filter sees registers, not paths, so it cannot pass those calls through. Measured 2026-10-11 on the 16-CPU workbox, with other lanes running:
  - each package's tests alone, observed against `-count=1`, two rounds: 2,060 s against 1,626 s of CPU time in total (+27%; `cmd/ergo` +24%, the legacy compiler package +28%, `scripts/gate` +43%). Wall time at a 1-minute load of 14–62 was 1,272 s against 822 s; an earlier measurement at load 13–73 gave 1,933 s against 1,551 s of CPU (+25%), with the wall times reversed, so the load swamps wall time;
  - the full gate, with every step and every Go test rerun: 108.2 and 135.5 s against 95.3 and 67.7 s on main (1-minute load 27–92 when each started, 68–91 when it ended; earlier pairs measured 99.1 and 149.1 s against 82.2 and 70.9 s, and 74.9–76.6 s against 50.1–60.8 s);
  - a gate with nothing changed: 4.6–7.0 s at a 1-minute load of 68–94, every Go test `(cached)` except the guard (below). On main, at loads of 62–75, the first no-op after a full run took 5.8 and 14.5 s (rerunning 1 and 7 test packages), and the second 5.5 and 3.2 s.

  A no-op stays a no-op only if no test reads what the gate rewrites. The gate therefore builds `bin/ergo` beside its cache and moves it into `bin/` only when its bytes change (`go build` touches its output even when it relinks nothing), and a test that builds a command inside the repository passes `-buildvcs=false`: VCS stamping runs `git status`, whose walk would make the result depend on every file in the working tree, build outputs included. For the same reason the gate's own tests declare its steps over the packages `durations.json` names instead of running `go list ./...`, which lists every directory in the module, including the ones the gate's own steps write. The guard is the exception: it must see every new package, so it walks the tree and reruns whenever a listing changes, such as when the gate writes `bin/`; it takes about a second.
- **Other steps** declare their inputs: repository paths, tool fingerprints (below), environment variables and installed directories. A step that walks a directory itself, rather than Git's view of it, such as the Foldkit snapshot check, declares that directory as installed: every entry on disk, files Git ignores included; a link out of it back into the repository contributes only its target. A file's digest carries its content and the permission bits that can change a result: the three executable bits, which a check can read and which decide what a step can run, and owner-read. Steps run as the checkout's owner, so no group or other read or write bit decides their access, and no check asserts one; checkouts made under different umasks share receipts. These steps replay a recorded pass while those inputs are unchanged. Receipts live under `$XDG_CACHE_HOME/ergo-gate` (by default `~/.cache/ergo-gate`), never in the tree, and every worktree shares them. Failures are never recorded.
- **Environment.** Steps that run `go test` receive only the variables `internal/testinputs/testenv` names, as Bazel's strict action environment and Nix's pure builds pass only declared variables: `PATH`, `HOME`, `TMPDIR`, `XDG_CACHE_HOME`, `XDG_CONFIG_HOME`, the go command's settings, the Go runtime's variables and `ERGO_TOOL_VERSIONS`. The gate log prints the list. Go test steps receive `ERGO_TOOL_VERSIONS`, a digest of the git and `sh` fingerprints and the values of every one of those variables, set or not. Observation records a read of it for every test that runs a program, so a Go test result cached under other tools or settings is not reused, and no other variable can reach a cached test. The `go` tool fingerprint of a cached step carries the same Go runtime variables: `GODEBUG=inittrace=1`, for example, changes what a Go program prints without changing its bytes. The runner sets umask 022 and `GIT_OPTIONAL_LOCKS=0`, and `GOGC=400` unless the caller sets `GOGC`.
- **Tool fingerprints.** A tool's fingerprint keys what the tool prints about itself (`--version`; for `go`, `go env` with the toolchain settings) and every byte the gate can locate that running the tool executes or loads, each under its absolute path:
  - `go`: the file PATH resolves to and the whole `GOROOT` that `go env` reports. That file may be a launcher that selects another toolchain (`GOTOOLCHAIN`); the reported `GOROOT` is the selected toolchain's, so its `bin/go`, compiler, linker and standard library are keyed.
  - `git`: the binary and its exec path (`git --exec-path`), whose helpers git runs.
  - Any other file that is not a script: the file.
  - A script (`#!`): nothing. A script can exec any file, and the gate cannot locate what it runs, so its fingerprint never matches a recorded pass, and every step that keys that tool runs. (Until 2026-10-26 a script inside an npm package, such as the `tsc` launcher, keyed its package closure; that rule went with the Node toolchain.)

  The bytes are keyed because another build that prints the same version must not replay a pass. The path is keyed too, never in place of the bytes, because the same build under another prefix may load its helpers from another place. Every installation is hashed again on every run: 0.6–1.0 s for all five tools of the time (go, node, bun, tsc and git) together and 1.6–2.6 s one tool at a time, at a 1-minute load of about 39 on this host's 16 CPUs (measured 2026-10-11, before the Node toolchain was removed; the three tools now keyed take at most that). The gate starts every fingerprint its steps name as soon as it starts, so this overlaps loading the files and the first steps. No digest is remembered between runs, so no file timestamp, which a coarse clock can leave unchanged across a same-size rewrite, decides whether bytes are hashed. On darwin the kernel kills a signed binary that was rewritten in place and run, and keeps killing that file after its bytes are restored, until a new file replaces it (measured on darwin/arm64, 2026-10-30): such a tool answers nothing, so its fingerprint differs from the one recorded with the same bytes, and every step that keys it runs. Not keyed:
  - the system shared libraries the dynamic loader maps (libc and the like), which belong to the operating system rather than the tool;
  - git subcommands found on PATH outside the exec path, which git looks up only when a command is not built in;
  - a wrapper named in `GOFLAGS` by `-exec` (which `go run` runs the program under) or `-toolexec` (which wraps every compile and link): the `GOFLAGS` string is keyed, the wrapper's bytes are not, and `GOFLAGS` is empty here;
  - git configuration (`~/.gitconfig`, `$XDG_CONFIG_HOME/git/config`, `/etc/gitconfig`), which can name programs git runs (`core.hooksPath`, `core.fsmonitor`, filters, `!` aliases) and change what tests see (`init.defaultBranch`): it is user state outside every tool installation, and isolating the tests' git from it (`GIT_CONFIG_GLOBAL`, `GIT_CONFIG_NOSYSTEM`) belongs to the tests that run git.

  An installation the gate cannot read, or a tool that does not answer the gate's question within 10 s, never matches a recorded pass. The gate never waits on a tool longer than that deadline plus 1 s: at the deadline the tool is killed, and a process it started that still holds its output open is cut off 1 s later. That process is not killed and may outlive the question. Questions run in the gate's own process group, so terminal signals (Ctrl-C, a hangup, `nohup`) reach them exactly as they reach the gate.
- **Log identity.** The second line is `gate: head <sha> tree <tree> clean=<bool>`, so a log names the commit it checked. `clean=false` means staged, unstaged or untracked (non-ignored) changes, submodules included even when a submodule's `ignore` setting hides them from `git status`; the gate still runs, and the line says the log does not certify that commit alone. Each step line ends with when the step started, so a log shows its critical path.
- **Process smokes** that drive the CLI run as Go tests in `cmd/ergo` (`*_smoke_test.go` and `*_process_test.go`). Each one works in a private workspace whose files are copied in the test process; observation makes what the CLI reads there inputs of Go's test cache too.
- **Test addresses.** A test learns a server's address from the server: the server binds port 0 and reports the address it bound (an `onListen` callback, or the program's `listening http://…` line), as `net/http/httptest` does. A test that must name an address before the server starts, or that binds it again after the server released it to prove the release, must keep the kernel from assigning the port to any other socket in between. `internal/testport` reserves the port for the whole test (off Linux, `testport.Reserve` skips the test). No test closes a probe listener and hands its port on: another test can take the port in between (#112).
