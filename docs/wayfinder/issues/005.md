# How can Go and TypeScript imports avoid binding boilerplate while exposing trust?

## Question

What default interop model lets ordinary Go/TS libraries be imported using their existing declarations and host values, while preserving explicit effect contracts and revealing the trust, mutation, nullability, callback, and cancellation boundaries?

The user prioritizes TypeScript-like adoption over repetitive handwritten extern bindings, citing friction in ReScript and Gleam. Decide how much automatic host-type checking is available, when declarations are trusted, where validation is required, and what behavioral metadata belongs in a shared package contract. Host-specific code need not become portable automatically.
