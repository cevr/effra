# Reachable runtime modules and small executable receipts

Implement the owner-established [small executable contract](../../specs/binary-reachability.md): select reachable runtime/library modules, keep unused imports/initialization out, preserve static lowering for fluent calls, and retain callback/provider/codec roots soundly. Compare abstraction candidates with an optimized idiomatic Go control and a TypeScript/Effect caller, preserving validation, ownership, cancellation and cleanup while exposing erasure/direct-lowering/retention and residual size/dispatch/allocation costs. The JS target may use generated or specialized effect-runtime modules, including static `match` lowering, only behind the pinned default Effect-compatible ABI and userland contract. Ship minimal and managed-effect size/dependency checks; extend the same matrix with codec/HTTP consumers as their tasks land. Report application size separately from the compiler distribution and JS external runtime.

This is a compiler/library boundary requirement, not permission to weaken lifetime or error guarantees. Full gate, raw byte/symbol/dependency receipts and independent review required before closure.

[Runtime source modules](runtime-modules.md) are an independent preparatory child: split platform source imports and validate explicit dependency selection while preserving today's all-source emission. Checked application roots and generated-output reconciliation remain blocked on native interfaces; preparation does not close this parent or establish smaller applications.
