# Does explicit run and contract inspection make the tiny language useful?

## Question

Can a runnable `.ef` slice make deferred execution, service provision, and selective error recovery easy to read, while rejecting missing requirements and exposing concise canonical contracts to agents?

Produce a Go compiler with a deliberately small syntax, runnable JavaScript/Effect output, contract diagnostics, and shared CLI/MCP inspection. Unsupported features must be explicit. Record compile timings as evidence, not a claim of Go-equivalent speed. The user's reaction to the artifact is required before resolving this ticket.

### Prototype assets

- [Runnable `.ef` example](../../../examples/main.ef)
- [Implemented surface and limits](../../prototype.md)
- [Read-only compiler MCP](../../mcp.md)
- Local branch: `prototype/compiler`. The artifact passed the repository gate. This is an artifact receipt; the decision resolution is recorded separately below.

## Resolution

Owner feedback on 2026-10-05, after reviewing the public runnable prototype and README, found the direction useful for a finite slice: Go-like simplicity with Effect-style guarantees, followed by a request for more showcases such as algebraic data types and pattern matching. This resolves the prototype's usefulness reaction only. It does not resolve the separate Go backend/lifecycle/cost parity question, package-boundary measurements or any other HITL ticket.

Public evidence: the [runnable `.ef` example](../../../examples/main.ef), [prototype limits](../../prototype.md), [read-only MCP surface](../../mcp.md), and [public README](../../../README.md). The source artifact and its receipt remain evidence for this finite reaction, not a claim of complete language, runtime or performance support.
