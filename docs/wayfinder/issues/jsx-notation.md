# One-to-one JSX view notation (VW6)

Implement the accepted Option B notation only after the ordinary view library and interop contracts are ready. A user-defined pragma selects the checked ordinary lowering semantics; the exact pragma spelling remains a design input. JSX is queued syntax sugar, not a new effect, type, ownership or reactive runtime model, and the compiler does not hard-code React/Solid adapters or a mandatory view-node architecture. Effect execution/runtime selection is likewise userland-selected through a lawful checked implementation rather than implicit execution.

## Acceptance

- Parse the finite element/fragment/attribute/quoted-text forms and, for a declared user pragma, desugar each accepted form one-to-one to the pragma's ordinary checked calls. This one-to-one notation exception adds no hidden provider selection, host element, event tracking, subscription or cleanup behavior, and does not require `View.Node`/`Client.Element` or any framework adapter API.
- Type the user-defined factory, module and fragment choices as ordinary declarations, with explicit accessor/delay calls where needed; privileged framework names and hidden evaluation semantics are rejected. Two unrelated same-target pragma programs must compile without compiler edits, and a selected runtime must expose its actual JS representation and ABI honestly.
- Preserve labelled arguments, source spans, formatter output, LSP hover/definition/completion and visible desugaring. Diagnostics and effect/service/ownership rows must equal the explicit call form.
- Cover typed URL/style/script attributes, required attributes, fragments, prop punning, ordinary `if`/`match` children and negative controls for unsupported spreads, dynamic names, invalid tags, effect values used as nodes and unsafe raw content. Preserve explicit types, effect/service/failure rows and ownership through lowering; no implicit Effect execution is admitted.
- Run the same accepted programs through Go/JS and the selected provider/runtime interop. React, Solid 2 and solid-yield corpus rows validate pragma/runtime interop rather than bespoke compiler adapters. Record parse/emission receipts and independent review; design snippets alone remain unverified. The durable [JSX pragma and target-qualified view record](../../research/jsx-pragmas-and-runtime-selection.md) owns the finite notation, source comparisons and rejected alternatives; selected runtime laws and evidence categories come from the [lawful runtime contract](../../research/lawful-runtime-contract.md).

The notation does not imply hydration, streaming, framework parity or current compiler support. Client mount ownership remains the separate VW4 lifetime bridge.

Prior art: TypeScript's per-file [`@jsx` factory](https://www.typescriptlang.org/tsconfig/jsxFactory.html) and [`jsxImportSource`](https://www.typescriptlang.org/tsconfig/jsxImportSource.html), plus Babel's [`transform-react-jsx` factory/fragment pragmas](https://babeljs.io/docs/babel-plugin-transform-react-jsx), show provider selection without fixing Effra's pragma spelling or semantics. They are source inputs, not current Effra support.
