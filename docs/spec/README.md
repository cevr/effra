# Ergo language specification, v0

Version 0, 2026-10-27. Ticket [#193](https://github.com/cevr/ergo/issues/193), part of the compiler track [#192](https://github.com/cevr/ergo/issues/192).

This directory is the normative specification of the Go-shaped Ergo language: Effect's guarantees with Go's spelling, compiled to Go (owner, 2026-10-26: "this will be effect for Go with this kind of new language as well"). `.ef` source is authoritative. The parser ([#195](https://github.com/cevr/ergo/issues/195)), the checker ([#196](https://github.com/cevr/ergo/issues/196)) and the linearity pass ([#197](https://github.com/cevr/ergo/issues/197)) implement this text.

## Scope

- **In scope.** Lexical rules and grammar, types, error and capability rows, resources, the runtime rules, the standard-library outline and the diagnostics of the core.
- **Sources.** The design sketches of 2026-10-26, numbered 8, 9 and 10, their two independent reviews, and the merged prototype compiler in [`prototypes/sketch9`](../../prototypes/sketch9/README.md) with its [receipt](../../prototypes/sketch9/RECEIPT.md). The [language evolution preview](../previews/2026-10-27-go-sketch.md) shows the language as of this version.
- **Out of scope.** The earlier `.ef` language, which [#205](https://github.com/cevr/ergo/issues/205) retired with its compiler ([retirement record](../receipts/retire-ef.md)). Its documents stay as design reference. [`docs/design.md`](../design.md) marks each section this specification supersedes.
- **One language.** There are no editions and no manifest: every `.ef` file is this language.
- **Terms.** Every domain term is defined only in the [glossary](../../GLOSSARY.md). These files state rules and link to it.
- **Direction.** [NORTH_STAR.md](../../NORTH_STAR.md) holds the pillars P1 to P7 and the tiebreaks. [PRIOR_ART.md](../../PRIOR_ART.md) holds the source comparisons.

## Conventions

- "Must", "must not" and "is an error" are normative. An error has a diagnostic code from [diagnostics.md](diagnostics.md).
- Each construct carries one status label:
  - **Implemented in prototype**: `prototypes/sketch9` accepts it and lowers it to Go, and its fixtures pin the behaviour.
  - **Partly implemented in prototype**: the prototype accepts a named subset. The section lists what is not yet implemented.
  - **Designed, not yet implemented**: decided in the sketches or by the owner, with no compiler support yet.
  - Since [#195](https://github.com/cevr/ergo/issues/195), the parser `internal/sketch/syntax` parses and formats every construct of all three labels. The labels state what the checker accepts: a parsed construct that the prototype checker lacks is S109 ([diagnostics](diagnostics.md#s109-outside-the-subset-or-reserved)).
- A design choice between options cites prior art in one line. The standing comparison set is Go, Gleam, ReScript, Elixir/OTP, MoonBit, Rust, Swift, Effect and OCaml/Koka.
- Examples are fenced as `go` because the surface is Go-shaped. They are Ergo source, not Go.

## Gaps

The prototype's behaviour and the sketches leave the points below unstated or in conflict. Each has a recommendation. A rule in another file that settles a gap says so.

1. **Total-catch default arm.** The sketches say a total `catch` has no default arm. The prototype's emitter adds one that passes `rt.Interrupted` on, because interruption is not a typed error. *Recommendation:* adopted as the rule in [rows.md](rows.md#catch): a `catch` covers the typed row only, and interruption and defects always pass through it. Lowering must keep that path.
2. **Interruption in a function with no error row.** The prototype panics with `rt.Interrupted` through `t.Check()`, and the nearest task boundary recovers it; `main` exits with status 130. *Recommendation:* adopted in [runtime.md](runtime.md#exit-causes): interruption is part of the exit cause, never of the error row. The lowering is free to choose the carrier.
3. **Type-switch totality.** The prototype accepts a type switch that omits a variant when the function needs no value after it (measured: a two-variant switch with one `case` checks with exit 0). The sketches say switches are checked for totality. *Recommendation:* a type switch over a union must name every variant or have a `default` arm, as Gleam, Rust and Swift require. The rule is in [rows.md](rows.md#totality); the prototype does not enforce it.
4. **`main` with an error row.** The prototype rejects it (S109). The sketches write `func main() error[ConnectFailed] needs Console`. *Recommendation:* allow it. The entry prints each cause and exits 1, or 130 when every cause is an interruption, as the current entry failure report does.
5. **Host capabilities for `main`.** The prototype gives `main` only `Console`. Decision #102 makes `Clock`, `Scheduler`, `Random` and `Console` ordinary interfaces bound by `wire`. *Recommendation:* the entry supplies a predeclared host wire with these four live providers. A test replaces any of them with `with`. The exact host set is open.
6. **Closed top-level wires.** The prototype requires a named `wire` to need no capability from its caller and to let no failure escape. The sketches give a named wire constructors whose rows join the `with` site. *Recommendation:* the closed rule is a prototype limit. The designed rule is in [rows.md](rows.md#wire).
7. **Wire entries as provider literals only.** The prototype rejects a constructor entry (S109). *Recommendation:* constructors are designed ([rows.md](rows.md#wire)); the parser and checker take both forms.
8. **Visibility (closed 2026-10-27).** Every sketch since the fourth relies on Go's capitalised export, for example an unexported field that makes `ParseQuantity` the only constructor. The owner chose explicit `pub` on 2026-10-08. Asked again with the recommendation "Go's capitalisation", the owner answered on 2026-10-27: "Yeah, let's go with your [recommendations]". *Decision:* a name is exported when it starts with an upper-case letter, and `pub` is superseded. The rule is in [grammar.md](grammar.md#visibility); the [NORTH_STAR tiebreak](../../NORTH_STAR.md#tiebreaks) records the change.
9. **Integer types.** The prototype has one integer type, `int64`, and the sketches use `int` and `int64`. *Recommendation:* [#81](https://github.com/cevr/ergo/issues/81) decides the numeric types. Until then, `int64` is the only integer type with checked meaning.
10. **Short-circuit operators.** The prototype rejects `&&` and `||` (S109) because hoisted calls would run out of order. *Recommendation:* allow them with Go's short-circuit order. The lowering must not hoist a right operand above the left.
11. **`catch e` binding and statements in arms.** The prototype's arms are single expressions with no binding. The sketches bind the error (`catch e { case X: … }`) and use `return` in an arm. *Recommendation:* adopt both, as in [rows.md](rows.md#catch). An arm is a statement list whose last statement yields the arm's value when the catch is an expression.
12. **Multi-subject type switch.** The sketches write `switch s, sig := s.(type), sig.(type)` with tuple cases and `_`. *Recommendation:* adopt it as the machine-step form, with totality over the product. It is designed only.
13. **Automatic release versus checked `defer`.** The 2026-10-26 sketch 9 made a resource linear with a checked `defer` and `build.Scope.Acquire`. The owner's later direction of the same day ("make it simpler so that defers are automatic") replaced that with automatic release. *Resolved 2026-10-27:* [resources.md](resources.md) follows automatic release. `defer` stays for statements that are not releases. `build.Scope` becomes a library for dynamic registration. The [#65](https://github.com/cevr/ergo/issues/65) body and the [#206](https://github.com/cevr/ergo/issues/206) table now say the same.
14. **Resources behind interfaces.** Review 9 (M2) showed that converting a resource to an interface without `Close` loses release authority. *Recommendation:* adopted in [resources.md](resources.md#conversions): that conversion is an error.
15. **Moves into aggregates.** The owner's rule lists four moves. Building a struct whose field is a resource also transfers ownership, as the `Postgres` example does. *Recommendation:* adopted in [resources.md](resources.md#moves) as a fifth move.
16. **Reserved names of the prototype's output.** The prototype reserves Go's predeclared identifiers, `rt`, `time`, `fmt`, `init`, `Error`, `timeout`, `duration`, names with `__` and names ending in `_` (S109). *Recommendation:* these are prototype limits. The main compiler mangles generated names, so only the language's own reserved words stay reserved ([grammar.md](grammar.md#reserved-names)).
17. **Capabilities in provider methods.** The prototype rejects a `needs` clause on a method and a capability call inside a provider method (S109). *Recommendation:* a provider method may use the capabilities its constructor captured, as Effect's layers capture their dependencies. A method signature still cannot widen the capability's row.
18. **Diagnostic codes.** The prototype's codes (S001, S101 to S110) are not in the main compiler's EF registry ([#79](https://github.com/cevr/ergo/issues/79)). *Recommendation:* the main compiler gives each rule in [diagnostics.md](diagnostics.md) an EF code, and keeps the rule text and fixture links.
19. **No fixture file for S107.** The missing-return rule is pinned only by a table test in `sketch/sketch_test.go`. *Recommendation:* add a probe file with `// want S107` when the prototype is next touched.
20. **Codec discovery by name.** The sketches find a type's codec by the names `ParseX` and `Wire`, as Go finds `TestX`. A rule keyed on a name risks the special-cased-library pattern the owner rejected. *Recommendation:* state it as a general method-set convention with laws in [#49](https://github.com/cevr/ergo/issues/49), so that a userland codec family can use the same rule.
21. **Go interop.** The 2026-10-26 sketch 9 first dropped user-level Go interop and then restored `import go` at the owner's request. Decision #9 maps Go imports automatically. *Recommendation:* `import go "path"` with the `go.Foreign` capability, as in [grammar.md](grammar.md#declarations). The mapping rules stay with [#32](https://github.com/cevr/ergo/issues/32).
22. **`Layer.fresh`.** There is no form for an independent build of one node inside a build. *Recommendation:* a contextual `fresh` inside `wire`, decided with [#37](https://github.com/cevr/ergo/issues/37).
23. **Generic surface.** The sketches use single capital letters as implicit type parameters (`func Map(xs []A, …)`). No rule says which names are parameters. *Recommendation:* [#135](https://github.com/cevr/ergo/issues/135) decides. The spelling in [types.md](types.md#generics) is provisional.
24. **Purity of function values.** Review 9 (M3) withdrew "an empty-row function type is pure". *Recommendation:* adopted in [rows.md](rows.md#footprints): a function type carries requirements only, and an unknown function value counts as impure.
25. **`duration` in signatures.** The prototype types duration literals and the `timeout.After` argument, but `func delay(d duration)` is S104, because `duration` is not one of its basic type names. *Recommendation:* `duration` is a basic type usable in every type position ([types.md](types.md#basic-types)). *Prior art:* Go's `time.Duration` is an ordinary named `int64` type, usable in every type position.
26. **Equality on `duration`.** `1s == 1s` is S109 in the prototype. *Recommendation:* `==` applies to every basic type, `duration` included ([types.md](types.md#operators)). *Prior art:* Go compares `time.Duration` values with `==`, as every integer-based type.
27. **Method calls on values.** The prototype calls a method only through a capability. A direct call such as `S{}.M()` or `v.M()` is S109. *Recommendation:* Go's method calls on values, including on a composite literal ([types.md](types.md#methods)). *Prior art:* Go method values and calls; Gleam has no methods and calls module functions instead.
28. **Repeated capability entry in one wire.** The prototype accepts two entries for one capability in one wire, and the later one wins (measured: `wire{ Store = Mem{V: "first"}; Store = Mem{V: "second"} }` prints `second`). *Recommendation:* a second entry for a capability in one wire is an error, S111 (designed), unless it is a `replace` of an embedded entry ([rows.md](rows.md#wire)). *Prior art:* Google Wire rejects two providers of one type in a set; Effect's `Layer.merge` lets the later layer win silently, which Ergo does not copy.
29. **Capabilities as values.** The prototype accepts a capability interface as a parameter and result type (`func identity(c Store) Store { return c }` checks), but a method call on such a value is S109, and assigning a struct value to an interface type (`func NewStore() Store { return Mem{} }`) is S108, because the prototype's assignability is identity plus the variant-to-union rule. Both are prototype limits. *Recommendation:* interface assignability by method-row compatibility ([types.md](types.md#interface-assignability)), and distinguish the capability from the interface type ([types.md](types.md#capabilities)). A capability name used as an expression, other than as the receiver of a method call, is an error: the bound provider cannot be passed, returned or stored. The same interface used in a type position is an ordinary interface type, and its values are provider values whose method calls carry the methods' declared rows. This keeps decision #102 (capabilities are ordinary interfaces bound by `wire`) and keeps ambient authority out of values. *Prior art:* Effect separates a service's tag (the requirement) from a service value; Scala 3 capture checking tracks capabilities apart from their types.
30. **Channels of resources.** v0 makes a channel whose element type is a resource an error ([resources.md](resources.md#channels)). *Recommendation for a later version:* a send moves the value; the channel's buffer owns values in flight; releasing a channel releases its buffered values; a failed or interrupted send leaves ownership with the sender. *Prior art:* Rust `mpsc` moves values into the channel and drops buffered values with the receiver; Go channels copy and leave cleanup to the programmer.
31. **`timeout.After` as a name-keyed prototype exception.** The prototype recognises `timeout.After` by its imported name: the parser gives it a trailing block, and the checker charges `Scheduler`, adds `timeout.Expired` and makes its block a failure target. That is the special-cased-library pattern the owner rejected. *Recommendation:* `timeout.After` is an ordinary library function over kernel primitives ([runtime.md](runtime.md#timeouts)): a trailing block is a function-literal argument ([grammar.md](grammar.md#expressions)), and a row-generic signature gives the same rows. The prototype's special casing stays as an exception until the main checker has trailing blocks and row-generic functions.
32. **Resource map keys.** v0 makes a map whose key type is a resource an error (R40 in [resources.md](resources.md#containers); S112, designed), because a key has no release owner under R34 to R37. *Recommendation for a later version:* a map with a resource key type is itself a resource and owns its keys; inserting moves the key in; a delete-and-return moves the key and value out together; replacing the value for an existing key releases the old value and keeps the old key, releasing the new key argument; releasing the map releases every key and value. *Prior art:* Rust's `HashMap` owns its keys and drops them with the map, and `HashMap::insert` on an existing key keeps the old key.
33. **A wire header clause: exposure or requirements.** The corpus (`sketch-eval-8/five/layers`, both `wire-effects` files) wrote `wire App uses Account, Invoice { … }`, where the clause meant the capabilities the wire exposes ("Store stays hidden"), while `uses` on a signature meant requirements ([rows-and-constraints.md](../research/rows-and-constraints.md) §7 item 9). *Resolved 2026-10-27* ([#217](https://github.com/cevr/ergo/issues/217)): two keywords, one meaning each. `provides A, B` lists what a named wire exposes, and the entries it does not list stay private to its build; `needs C, D` lists what its providers require from the `with` site, joined into that site's row, as Effect's `Layer<ROut, E, RIn>` keeps provided and required services apart. A header may state both, `provides` first: `wire App provides Account, Invoice needs Config { … }` ([grammar.md](grammar.md#extensions-beyond-the-written-productions), [rows.md](rows.md#wire) rule 8). The corpus copy now says `provides`. The parser of [#195](https://github.com/cevr/ergo/issues/195) admits both clauses, and the bridge refuses them with S109 until the checker of [#196](https://github.com/cevr/ergo/issues/196) checks them.
34. **One provider for several capabilities: `Clock, Scheduler = testing.VirtualClock{}`.** The corpus binds one value to several capability rows in one wire entry. The parser of #195 admits several keys before `=`, as Go's `var a, b = …` admits several names ([grammar.md](grammar.md#extensions-beyond-the-written-productions)), and the bridge refuses it with S109. Its meaning (one value shared by several rows, or one value per row) is the checker's to define. Owner: [#196](https://github.com/cevr/ergo/issues/196). *Prior art:* Effect's `Layer.mergeAll` builds one layer that provides several services.

Gaps 35 to 47 come from the [#101 spike](../research/actor-library.md) (A1 to A13 there). The `actor` package is library code only if these general rules exist. Each also serves tasks in containers and channels, queues ([#64](https://github.com/cevr/ergo/issues/64)), `tasks.Set`, RPC replies ([#53](https://github.com/cevr/ergo/issues/53)) and batch waiters ([#68](https://github.com/cevr/ergo/issues/68)).

35. **Consuming parameters and receivers (A1, [#197](https://github.com/cevr/ergo/issues/197)).** R19 names the consuming calls: `Close`, `Task.Wait`, `Task.Stop` and an actor's `Stop`. A library type such as `actor.Reply` needs its own consuming method (`Send`). *Recommendation:* a parameter or receiver whose body consumes or moves it is consuming, and a call moves the argument. The checker infers it and records it in the exported interface summary, as it does for concurrent parameters. R19's list becomes a consequence of the rule. *Prior art:* Rust by-value `self`; Swift `consuming` methods.
36. **Resource unions (A2, #197).** No rule says whether a union with a resource variant is a resource. *Recommendation:* it is (R1 extended); a type switch on an owned union moves the variant into the case binding.
37. **Channels of resources (A3, #197, #64).** Gap 30's later rule is needed now: an actor's mailbox holds messages with a reply. *Recommendation:* adopt Gap 30's recommendation. A send moves the value, the buffer owns values in flight, and a failed send leaves ownership with the sending function, whose scope releases it. The receiving half is the same rule: when the last owner of a channel releases it, its buffered values are released. A value nobody can receive is therefore released exactly once. A reply slot is a channel that the asker and the reply share, so a late answer to a detached asker is released by whichever share is released last; the Go lowering implements this with a one-shot state ([`actor.go`](../../prototypes/actorlib/actor.go), `slot`). *Prior art:* Tokio `oneshot`: dropping the receiver makes `send` return the value to the sender, and dropping the channel drops a value in flight.
38. **Consuming a resource field in place (A4, #197).** A handler answers `m.Reply.Send(v)`, which consumes one field of an owned message; R39 forbids moving a field out. *Recommendation:* consuming a field in place is allowed on an owned aggregate; the field is then consumed, and the generated `Close` (R3) skips it. Moving the field out stays an error. *Prior art:* Rust partial moves.
39. **Owned parameters in function types (A5, [#196](https://github.com/cevr/ergo/issues/196), #197).** A handler `func(S, M)` must own `m` to consume the reply in it, and a function type has no body to infer A1 from. *Recommendation:* a function type marks an owned resource parameter; a call through it moves the argument. The spelling is open. *Prior art:* Swift `(consuming T) -> U`.
40. **Generic types with row parameters (A6, #196, [#135](https://github.com/cevr/ergo/issues/135)).** `actor.Reply[T, E]` and `actor.Actor[M, E]` carry an error row as a type parameter, and `Reply[int64]` should mean an empty row. *Recommendation:* a generic type may take row parameters, and an omitted trailing row argument is the empty row. [types.md](types.md#generics) rule 3 covers only rows that pass through.
41. **Failures as values (A7, #196).** A library that carries a typed failure from one task to another, as a reply does, needs a value form of an outcome. *Recommendation:* a prelude `Exit[T, E]` with `Succeed(v)`, `Fail(e)` and `x.Get() (T, error[E])`. *Prior art:* Effect `Exit`; Gleam `Result`. A function literal that returns the failure works under the current rules, at one closure per value.
42. **Release of a value typed by a type parameter (A8, #197; lowering [#190](https://github.com/cevr/ergo/issues/190)).** Generic code that owns a value of type `M` must release it when `M`'s instantiation is a resource. *Recommendation:* the checker treats such a value as possibly a resource. The lowering may test for `Close` on cold paths; a hot path needs per-type release passed through the generic dictionary or an argument, measured under #190. A `Close` test finds only a value that implements `Close` itself, so the same gap covers general drop glue: a struct with a resource field (R1) and a slice, array or map of resources (R34, R37) are resources with no `Close` of their own, and the compiler must generate their release, each field in reverse declaration order and each element, with every remaining release run after a defect, under the releasing task's masked boundary. The #101 prototype hand-writes it only for its own message envelopes and pins the other shapes as unreleased (the note's Q2).
43. **The result of `Task.Stop` (A9, [#207](https://github.com/cevr/ergo/issues/207), [#13](https://github.com/cevr/ergo/issues/13)).** [runtime.md](runtime.md#tasks) Tasks rule 4 does not say what `Stop` returns. `runtime/rt` returns defects only and drops the typed failure of a task that ended before the stop, which `actor.Actor.Stop() error[E]` needs. *Recommendation:* `Stop` returns the task's typed failure when the task ended with one before the stop, and its defects; the interruption it caused is dropped.
44. **Escaping function parameters and shared handles by structure (A10, #196).** [types.md](types.md#function-values) rule 2 says a function parameter is non-escaping "unless its type says otherwise", with no spelling; `actor.Start` and `tasks.Set.Go` keep their function. [runtime.md](runtime.md#tasks) Tasks rule 6 and R1 name "actor handles" among shared handles and resources. *Recommendation:* spell the escaping mark in the function type, and make sharing structural: a value whose fields are all synchronised handles copies into tasks. An actor's owner handle is a resource because it holds a `Task`, with no name in the rule.
45. **The copy at a task boundary (A11, #196, [#81](https://github.com/cevr/ergo/issues/81), [#211](https://github.com/cevr/ergo/issues/211)).** [runtime.md](runtime.md#tasks) Tasks rule 6 says values copy into a task, and [types.md](types.md#structs) Structs rule 6 says a copy is a snapshot. Neither says what the Go lowering emits for a slice or a map, which Go shares by reference, or where the copy happens when a value leaves a task through a channel, a reply or a callback result. *Recommendation:* every value that crosses a task boundary (a capture into `go`, a channel send, an actor message, a reply, an agent result, a machine snapshot) is a copy that shares no mutable storage: the lowering clones each reachable slice and map, per static type, and emits nothing for a type with none. Move on last use skips the clone. A resource moves and is not copied. The `actorlib` prototype applies the rule at run time with a cached per-type plan; its measured cost is in the note's Q8.
46. **The type of a machine value (A12, #196, [#57](https://github.com/cevr/ergo/issues/57)).** [runtime.md](runtime.md#machines-and-actors) item 1 declares `type X machine[S, E] { initial v; step f }` with two type parameters, so a function that takes any machine cannot name the step's output `O`, failure row `F` or requirement row `R`. *Recommendation:* a machine declaration's value has the prelude type `Machine[S, E, O, F, R]`, a struct with `initial S` and `step func(S, E) (Decision[S, O], error[F]) needs R`; `O`, `F` and `R` are read from `step`'s signature. This needs Gap 40 extended to `needs` row parameters, and a function-typed field whose `needs` row is charged where the value is built (Gap 17's constructor capture).
47. **A boundary releases a successful result it discards (A13, [#13](https://github.com/cevr/ergo/issues/13), [#207](https://github.com/cevr/ergo/issues/207); lowering [#190](https://github.com/cevr/ergo/issues/190), [#197](https://github.com/cevr/ergo/issues/197)).** [runtime.md](runtime.md#exit-causes) Exit causes rule 5 makes a stop beat a body's success, and `rt.Run` and `rt.Scoped` then return the zero value. When the discarded result is a resource or holds one, nobody releases it. The #101 note (Q2) shows three forms: an actor reply taken by a task that is stopped before its task boundary; a callback's result that `rt.Scoped` zeros when a release in the scope requests a stop; and, with the `defer s.End(&err)` spelling, a candidate result left beside an interruption, which the caller must not close because a failed function's value is not valid. *Recommendation:* every boundary that applies stop-wins to a successful result, a task's or a scope's, releases that result, as an owner scope releases what it owns (R5); and the lowering of a function result records which value an unsuccessful exit still owns, so that no zero value is closed. The same rule covers every task or scope whose body returns a resource, not only actors.
