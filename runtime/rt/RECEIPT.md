# runtime/rt receipt

Package `rt` is the kernel runtime that emitted sketch code links against (#198). It implements the runtime rules of `docs/spec/runtime.md` (I1, I2, G1, G2) and the release rules of `docs/spec/resources.md` (R5, R7, R8, R9, R27). It has no Effect runtime code and does not import the prototype. The start point was `prototypes/sketch9/sketch/rt`. That package's task tree, `After` and review tests were rewritten here, not copied as they were.

## Design notes

- **Stop flag.** The stop flag is an `atomic.Bool`. The prototype closed a channel and polled it with `select`. The poll is now `stopped.Load() && mask == 0`: one atomic load while no stop is requested. The stop channel exists only for blocking waits. `Done` makes it on first use, so a task that never blocks never allocates one. The benchmarks decided this: in round 2 the atomic poll cost 1.4–1.6 ns and a `select` on a channel, the prototype's poll, cost 5.2–5.5 ns. Round 3 measured 2.0–2.3 ns against 6.0–7.0 ns under higher load.
- **Masks.** Only the task's own goroutine changes or reads its mask regions, so they are not part of the atomic word. The first version packed the depth and the flag into one `atomic.Uint64`. Measured with the entry layout before the change below, Acquire+release cost 44.7–49.5 ns with the packed word and 41.9–45.2 ns with the split field (three runs each). The split costs nothing and removes four read-modify-writes from each acquire and release. `Mask.Interruptible` is the poll pattern. Regions nest.
- **Region stack (round 4).** The mask regions are an explicit owner-local stack, innermost on top. Each entry has a kind. *Protecting* is a release, a defer body (`Task.Mask`) or a `GoMasked` body. *Acquiring* is `Acquire`'s registration step. A restore (`Mask.Interruptible`) pushes an entry of its own kind, never a copy of the outside kind (round 6). The entry records two bits, computed when it is pushed from the stack below the restored region: whether that outside state is masked, and whether it shields a child (round 7; an unmasked outside never shields, so there are three restore kinds in all). When that state is unmasked, the restore unmasks the owner. When it is masked (an outer mask or an acquisition), the owner stays masked, so an inner restore never unmasks an outer region (I2). Round 5 copied the outside kind instead. A restore under an ordinary `Acquire` then copied `acquiring`, and the shield walk skipped it and reached the protecting region the restore had lifted. That shielded the restored child, and a masked owner waiting on it could deadlock. The task is interruptible when the stack is empty or its top is interruptible. The shield walk goes down from the top and skips acquiring entries: the nearest protecting entry shields a child, a restore entry stops the walk and returns the shield state it recorded for its outside, and an empty walk does not shield (round 7). This is the ZIO and Effect restore rule: restore returns to the interruptibility of the region enclosing the restored one, not to a fixed interruptible state, and the region enclosing a finalizer is uninterruptible. So a restore under an ordinary `Acquire` (outside: acquiring, then nothing) starts cancellable children, and its masked owner cannot deadlock on them. A restore under an `Acquire` inside a cleanup (outside: acquiring, then protecting) keeps the cleanup's shield, and the cleanup still completes. A restore of a `GoMasked` body returns to the empty outside and does not shield. Round 6 made every restore unshielding; that let the ambient stop reach a helper of an outer cleanup through an inner restore, which round 7 reverts. A child keeps the admission mode fixed at its start after the restore returns. Acquisition masking protects only the acquiring task's own registration window. It is not a cleanup region, so it must not hide a cleanup around it: release, then `Acquire`, then a helper is shielded, and so is restore, then release, then `Acquire`, then a helper. An ordinary `Acquire` outside any cleanup still starts cancellable children. Every entry pops on every exit through `defer`, panics included. The round-3 counters (`mask > acquiring`) were replaced because a restore inside `Acquire` reset the depth but not the count, which left a release nested in that restore unshielded. Seven entries and the top kind share one 8-byte word. Deeper nesting spills to a slice with an `int` depth and no limit (round 5). A round-4 `uint16` cap panicked when `Scope.End` opened its release mask, before any release ran, and so dropped the cleanup and the body's failure. `TestDeepMasksKeepCleanup` opens 65,535 masks to cover this.
- **Child interruptibility.** `Go` starts a child interruptible, even inside a masked region such as an `Acquire`. This follows the pinned Effect 4 default, where fork is interruptible unless asked to inherit. `GoMasked` is the explicit inherit mode. Its body runs inside one masked region and receives that region as `restore`. `restore.Interruptible` opens an interruptible sub-region, as in ZIO's `uninterruptibleMask` and restore and in Effect's restore. A stop that the masked body never observes does not replace its result. A child that starts while its owner is inside a release is release-owned and shielded. A release here means a scope release, a defer body or a `GoMasked` body that is not hidden by a nearer restore. An `Acquire` nested in that release keeps the protection. A release entered inside a restore inside `Acquire` pushes its own protecting entry, so its helpers are shielded too. The ambient stop cascade from the owner does not reach a shielded child, whether the stop arrives before or after the child starts, so the release runs to completion (I2, R9). Its handle's `Stop`, a timeout and its scope's drain still interrupt it directly, and the release-local scope drains it before the release returns. The shield is a flag fixed on the child before it is linked. The cascade goroutine reads only that flag, never the owner's region stack. Ordinary `Go` outside a release stays reachable by the cascade, and so does a child started inside an `Acquire` that no cleanup encloses. Prior art: Trio shielded cancel scopes, which block outside cancellation but keep inner timeouts; Effect's uninterruptible finalizers; Go `context.WithoutCancel`.
- **One boundary.** `Run` is the task boundary. Every child started by `Go` runs its body through `Run`, and emitted `main` calls `Run` for the root (`os.Exit(rt.ExitCode(err))`). A later law adapter (#124) can use the same entry. `Run` and `Scope.End` share one finalization step (`settle`): a recovered panic becomes a defect, and a stop the task can observe beats success (Exit causes rule 5). This applies to empty scopes too, and to a stop that arrives during a release, which is observed when the release mask closes.
- **Exit accumulator.** `Cause` keeps reasons in order: the body's typed failure, each release defect (`InRelease`), and at most one interruption. Errors are canonical. A lone typed failure stays itself, a lone interruption is `Interrupted`, and anything else is `*Cause`. `Failure` gives a catch only a lone typed failure (rows.md catch rule 6, law R6).
- **Release.** `Scope.End` is deferred directly, so it can recover the body's panic. It releases in reverse order, masked. Each release recovers its own panic as a defect, so a later release still runs (R9). `Acquire` runs `open` and the registration in one masked step (R8).
- **Release for an outside scope (lower-v1 stage 3b-runtime).** `Release(t, c, f, classify, after)` runs one release of a scope whose entries rt does not hold (runtime/v1's frame list) as `runReleaseTraced` runs its own. A panic of `f` is handled in causal order. First, on a traced tree, only the calls `f` opened are closed (the floor is `traceDepth` at its start). Next, `classify`, inside the recover, gives the defect value, which the caller keeps (runtime/v1's `*Panic` with its stack), and the carried exit; the defect is recorded as raised in a release and links the innermost unwound call. Last, `after`, if any, ends what the release ends after its body, with the carried exit, so nested releases report after the panic event. A panic that escapes `classify` or `after` is one more release defect, never an escape. The release event follows on every path. The caller masks. It is the only rt addition for v1 tracing (`TestReleaseRecordsAsAScopeRelease`, `TestReleaseKeepsAPanicOfItsFollowUp`).
- **Allocation-free registration.** A scope keeps four entries inline. An entry is a releaser and its resource. A releaser is a struct with at most one func field, which Go stores in an interface without allocating. The first version stored `closeWith[R]` as a func value. A func value of a generic instantiation binds its dictionary in a 16-byte heap closure, so that version measured 90–113 ns and 1 alloc/op. The releaser layout measures 29–31 ns and 0 allocs/op.
- **Tasks.** A `Handle` embeds its `Task`, so a start allocates the handle, its done channel and the goroutine. Children form an intrusive sibling list under the parent's mutex, so linking a child allocates nothing (the prototype used a map). `Interrupt` takes locks ancestor first. `detach` takes only the parent's lock, so a stop walk cannot deadlock with a finishing child.
- **Bounded ancestry (G2 rule 3).** The parent pointer is a live cancellation link only. It is an `atomic.Pointer`, so `Parent()` is safe from any goroutine while the task finishes. `detach` drops it when the task finishes, and a handle drops its owner when it is consumed. A finished task therefore retains no ancestors. Diagnostic ancestry is a copy: a defect records its chain as at most 32 value frames while the task still runs. A test builds a 129-deep chain that has finished, then checks with weak pointers that the leaf keeps no ancestor reachable.
- **Wait.** `Wait` checks the owner's stop before the completion fast path, and again after it wakes. If the owner is stopped, `Wait` returns the task's defects and then the interruption, even when the task has already finished.
- **After's unwind boundary.** Every exit of `After` passes one deferred boundary, including a panic in the `Scheduler` or `Timer` provider. The boundary stops and drains a child that is still running, stops the timer as a release, and adds each cleanup defect after the exit it already holds.
- **Normalization (laws R3, R4, R6, R8).** `Stop`, an interrupted `Wait` and an expired `After` keep the stopped task's defects. They drop its interruption and an abandoned typed failure, so a lone `Expired` stays a catchable typed failure (runtime.md Timeouts rule 4). The spec phrase "body cause plus `Expired`" is read this way: the defects of the body's cause survive, then `Expired`.
- **Law suite seam (#124).** Each R1–R15 law that applies to this layer can be driven from outside the package. A test can see the task identity and chain (`ID`, `Span`, `Chain`), every reason of an exit (`Cause.Reasons`), the stop and mask state (`StopRequested`, `Masked`) and the timers (`Virtual.AwaitTimers`, `Pending`, `Advance`), and it enters through `Run`.
- **Exit transport.** `Scope.End(nil)` and `Handle.Close` carry an exit through code with no error row inside an unexported `transport` value, and a recovery unpacks only that type. Any other panic value, a typed-nil or forged `*Cause` included, is a defect recorded as it is. Recovery never dereferences the payload, so it cannot panic itself and skip cleanup or mask restoration. Every `*Cause` method that reads is nil-safe.
- **Mutation receipts.** `mutants-r3.sh` in the unit directory applies 15 mutants. Each must build, then fail its named test with the intended assertion. Build errors count as invalid mutants, not kills.
- **Known gaps, carried to #124 and the observability work.**
  - A completed, unobserved child's typed failure is dropped at normal scope close. R3 needs a finer classification.
  - Virtual time fires due timers in deadline order, ties in arming order, but does not wait for managed continuations to quiesce (R14).
  - A defect records no start site (G2 rule 1); it records only the task and span chain.

## Tracing (#188)

The research note is `docs/research/traceability.md`. The unit directory is `/home/exedev/.cache/baton/wf10/trace-188`.

- **Off by default.** A tree is traced only when its root comes from `TracedRoot(span, tracer)`. Each task holds one `*tracer` pointer, which it inherits when it starts. The pointer took the word that moving `shielded` beside `stopped` freed, so `Task` stays 136 bytes and `Handle[struct{}]` stays 176 bytes. A start still allocates 3 objects and 320 B. `TestTraceHookKeepsTaskSize` pins the sizes, and `TestTraceOffAddsNoAllocs` pins the allocation counts 0, 3 and 0.
- **Emission points.** `Run` raises `start` and `body-exit`. `Interrupt` raises `cancel-request` when the flag flips, so each task in the cascade gets one. `Wait`, `Stop` and the join in `After` raise `observe`. An interrupted join raises none (law R4). The deadline path of `After` raises `deadline` for the child. A release raises `release` on every exit. A recorded defect raises `panic`. Emitted code raises `call` and `call-exit` through `Task.TraceCall` and `Task.TraceCallExit`, and `interrupt`, `construct` and `handler` through `Task.Trace`; each inlines to one load and a compare. The poll (`Stopped`, `Check`) has no emission point. `AfterSpan` is `After` with the child's span given, so a trace and a defect chain name the timeout block.
- **Occurrences and links (round 2).** Every event gets an occurrence ID from one atomic counter per tree, so an event that happens before another has the smaller ID. The runtime records links instead of leaving them to a reader. The tracer keeps, per task, the latest typed-failure occurrence that no handler consumed and the error it carried (a failure travels by return inside one task to a handler or to the body exit), the task's first `cancel-request`, the open capability calls, and the task's body-exit until its owner observes it. It also keys each defect's `panic` by the defect's chain. A `handler` links and consumes the latest failure. A `call-exit` links its call. An `observe` links the child's `body-exit`, and a completed `Wait` or a completed `After` join carries a child's single-failure exit to the owner. A deadline becomes the owner's latest failure, because the owner receives `Expired`. An interrupted join forgets the child's entry. `TestTraceHandlerLinksTheFailedCall`, `TestTraceHandlersLinkTheirOwnDeadlines`, `TestTraceChildFailureLinksThroughBodyExit` and `TestTraceDefectClosesTheOpenCall` check the links.
- **One origin per exit reason (round 3).** A `body-exit` has no link. `Event.Origins` gives each reason of the exit its own origin, in `rttrace.Reasons` order: a typed failure the failure occurrence it came from (round 4, below); a defect its own `panic` (by its chain); an interruption the first `cancel-request`; otherwise 0. A cleanup defect therefore never stands in for the body's failure (round-2 review M1). `TestTraceCompoundExitLinksEachReason` covers a failure with one and with two cleanup defects, two cleanup defects alone, and a failure with an interruption, all through `Scope`.
- **Every unwind closes its calls (round 3).** `Cause.recovered` takes the open-call depth at which its region began (`Run` 0, `Scope.depth` from `NewScope`, each release, `After`, the timer stop). On a traced tree it first closes the calls opened above that depth, innermost first, each with a `call-exit` carrying the transported exit, `interrupted`, or the defect; then it classifies the panic as before. A release closes only calls it opened, and a scope inside a call leaves that call to its own exit. A call already closed is not reported again. Masks and exit classification are unchanged. `TestTraceUnwindClosesCalls` (body or release, crossed with defect or interruption, round-2 review M2), `TestTraceReleaseUnwindKeepsOuterCall` and `TestTraceScopeUnwindKeepsOuterCall` check it. Off, a scope adds one compare in `NewScope` and an 8-byte `depth` field; `After` and the timer stop add one compare each; a release adds one compare and keeps a small frame, because the traced release runs in `runReleaseTraced`. `Task.Trace` raises only `handler`, `construct` and `interrupt`; other kinds passed to it are not raised.
- **Stack depth on the traced path (round 2).** Passing the `Event` by value through `traceExit`, `emit` and `raise` gave each frame its own copy. A new task's body-exit then outgrew the goroutine's first stack, and the stack copy cost about 2.5 µs per traced spawn (CPU profile: `runtime.copystack` under `Recorder.Event`). Round 2 passed it by pointer. Round 3 (`Origins`, 136 bytes) brought the copy back, 3,429 ns per traced spawn by minimum (`bench-r3-prefix.txt`): dereferencing the pointer for the `Tracer` call had taken a temporary and then the arguments. Now `InRelease` sits beside `Kind` (128 bytes), `raise` takes the `Event` by value and passes its own parameter on, and the body-exit goes through `raiseExit`, which holds it twice. The off path is unchanged: Run's frame is 0x70 as in round 1, and `Stop`'s grew from 0x28 to 0x30 for the carry argument.
- **An origin names an occurrence, never an equal value (round 4).** Round 3 linked a failure reason to the task's latest failure when the two errors were equal, so two calls that each failed with an equal value both linked the second call (round-3 review M1). Now each task keeps its unconsumed failure occurrences (at most 16, `maxFailures`; past that the oldest drops and the task is marked lossy), each with the error value it carried. A failure reason links the one occurrence whose error has the same interface identity: the same type word and the same data word (`identOf`), so the same stored value, not an equal one. Holding the error keeps its storage alive, so its address cannot be reused while it is pending. When two reasons share an identity, two occurrences do, or the task is lossy, the reason gets 0 and the query reports the candidates. Equal failures of a zero-size type (`Missing{}`) or of a constant in static data share one identity, so for them the runtime records no origin: the value cannot carry the occurrence. Wrapping each failure in a traced-only error (Go's `%w` route) was rejected because it would change what an emitted `==` or type switch sees with tracing on. `TestTraceEqualFailuresNameTheirOwnOccurrence`, `TestTraceFailureOriginNeedsTheSameValue` and `TestTraceDroppedFailureRecordsNoOrigin` cover it, with sketch9's `TestKernelEqualFailureProbes` through the recorder, writer and query. Limit: hand-written Go that drops a zero-size failure and then returns an equal one links the dropped occurrence; emitted code never drops a failure.
- **First-stack guard (round 4).** `TestTraceExitStaysOnTheFirstStack` measures, by stack addresses and not by time, how deep a new task's traced body-exit reaches below its body frame: 512 bytes on go1.27.0 linux/amd64. Each word added to `Event` adds 16 bytes, because `raiseExit` holds the `Event` twice. Padding located the cliff: at 624 bytes (seven words) a traced spawn still cost 1,339 to 1,741 ns, and at 640 bytes (eight words) it cost 2,997 to 3,495 ns, the stack copy (two interleaved runs each). The test fails past 576 bytes, 48 bytes (three words) before the cliff, and fails when `Event` grows past 128 bytes. It skips under `-race` and off amd64, where the budget was not measured. It passed 200 runs in a row (`-count 200`) and failed with a five-word pad (592 bytes).
- **No Event literal in a hot frame.** An `Event` literal built inside `Run` grew Run's frame from 0x60 to 0xc0 bytes even with tracing off. The first interleaved run measured spawn+wait about 90 ns slower than base (`bench-r1-prefix.txt`). Every emission point now calls a small `//go:noinline` helper (`traceTask`, `traceExit`, `childEvent`, `traceAt`, `traceCall`, `traceCallExit`, `traceDefect`), and only that helper builds the `Event`. Run's frame is now 0x70 for `struct{}` against 0x58 on base, and spawn+wait matches base within the noise (below).
- **A tracer that panics** is disabled for its tree. `raise` recovers the panic and sets `broken`, so the panic never joins the program's cause and never skips a release (`TestTracePanickingTracerIsDisabled`). A tracer must not block. It runs on the emitting goroutine, sometimes under the task's mutex (the cascade) or in a masked region. The bounded recorder in `rttrace` never waits: one atomic add reserves a slot, and a full recorder counts the event as dropped.
- **Recorder and writer** are in `runtime/rt/rttrace`. `rt` has no buffer and no encoding. The writer encodes its fixed shapes by hand, because `encoding/json` added about 1.48 MB to each example binary. With the hand encoder the trace switch costs about 62 KB per kernel-mode binary (`examples-r1.txt`).

## Prior art

- Go `context`: the cancellation tree. Ergo keeps the downward stop and adds a drain: `Stop` waits for the work and its releases.
- Effect `Fiber`, `Scope` and `Cause`: the guarantees. Release runs once on every exit. Interruption is not a typed error. A cause keeps every reason. In pinned Effect 4, fork is interruptible by default and inherits only on request.
- ZIO `uninterruptibleMask` with restore: the explicit masked start (`GoMasked`) and its restore.
- Trio nurseries and Swift task groups: structured lend. A scope stops and drains its tasks before it releases the resources it acquired earlier.
- Erlang/OTP links: defect propagation. A child's panic reaches the joiner with the chain of task and span IDs.
- Tokio cooperative budget: cooperative interruption at the points the compiler inserts.
- Cats Effect `MonadCancel` and `uncancelable`/`poll`: masks and the poll pattern.
